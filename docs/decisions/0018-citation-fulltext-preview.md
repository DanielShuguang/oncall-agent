# 0018 · 引用跳全文的可见性

- 状态：已采纳
- 日期：2026-11-09
- 后续：[ADR-0019](0019-document-level-access.md) 把这里的「同一可见性」收紧成文档级（`public` / `roles`，召回前过滤）
- 相关：[05-rag-design](../05-rag-design.md) §6、[03-api-contract](../03-api-contract.md) §5、[07-frontend-design](../07-frontend-design.md) §6

## 背景

W5 D24 的「引用跳全文」一直挂 ◐：引用角标只能打开切片片段，
`GET /admin/kb/documents/{id}` 又是管理员接口，普通员工看不到上下文。
之前的记录写的理由是「跨用户读原文需要单独授权」，于是这件事被搁置。

问题是这个理由站不住：同一条链路（`chat → retrieve → citation`）已经把
**切片正文**交给了员工，答案里的 `[1]` 附带的 `snippet` 就是原文。
全文只是把同一批切片补上前后文，不产生新的信息暴露面。

## 候选方案

| 方案 | 做法 | 代价 |
|---|---|---|
| A. 维持现状 | 只有管理员能看全文 | D24 做不完；员工排查时只能看半句话 |
| B. 文档级 ACL | 新增「谁能看哪篇文档」的授权模型，预览与检索各查一次 | 要新表/管理页/迁移；检索侧若不过滤，ACL 形同虚设；若过滤，等于把 RAG 的权限体系重做一遍 |
| C. 预览继承检索可见性 | 任何已登录员工可凭 `document_id` 读全文；不提供列表/浏览；管理操作仍 admin | 知识库整库对员工可读（但本来就能被检索到）；无按文档粒度控制 |

## 决策

选 **C**，并把边界写死：

1. `GET /api/kb/documents/{id}/preview` 只要求**登录**，不要求管理员；
2. 刻意**不提供** `GET /kb/documents` 列表：员工只能凭已知的
   `document_id`（UUID，不可猜）打开，不能浏览或导出整库；
3. 接口**不校验**该 id 是否真的出现在调用方的引用里——那需要把预览绑定到
   `run_id` 并校验归属，会把「从历史回答里翻到的引用」和客服/审计场景一起挡掉；
   当前用「无列表 + 不可猜 UUID」收敛，风险与检索本身同级；
4. `/api/admin/kb/*`（列表、上传、重建索引）仍然只属于
   `ONCALL_ADMIN_ROLES`；
5. 单次预览上限 200 个切片 / 20 万字符，超出返回 `truncated: true`；
6. 焦点优先 `chunk_id`、`ord` 兜底；都对不上时 `focused_chunk_id: null`，
   前端明说「引用位置未找到」——**不猜段落**。

## 理由

- 可见性只有一份实现，预览和检索不会漂移。B 方案的 ACL 若只在预览生效，
  就是自欺欺人；若同时在检索生效，则需要先设计「召回前过滤」，
  那是另一个里程碑的工作量，而当前语料本来就是全员可读的制度文档。
- 不做列表是成本最低的收敛：知识库的「发现」面仍然只有管理员，
  员工拿不到可浏览的文档集合，只能打开已经知道的 id（通常来自自己的引用）。
- 与 ADR-0014（工具覆盖存库、定义留代码）同一条思路：能用现有边界解释的，
  不新引入一套授权体系。

## 后果

- 员工点击引用能直接看到整篇上下文并定位到引用段；管理员接口权限不变。
- 预览是**按切片重组**，不是原始文件渲染：PDF 排版、表格样式会丢，
  UI 底部需要写明；原始文件仍在知识库里，需要时可下载。
- 文档重新上传后 `document_id` 会变，旧引用打开返回 `404`；
  同一文档重切后 `chunk_id` 变化则退到 `ord`，再对不上就不标焦点。
- **如果将来引入文档级 ACL（密级、部门可见性）**：必须先在检索侧过滤，
  再把同一个过滤函数复用到预览；否则预览会成为绕过点。
  这一条写进 docs/05，改检索前必须重读本 ADR。
- 覆盖：`tests/test_rag_preview.py`（窗口/焦点/截断）、
  `tests/test_kb_preview.py`（员工可读、404、401）、
  `web/src/features/chat/citation.test.ts`（定位文案）。
