# ADR-0077：窄屏会话抽屉的焦点陷阱与背景滚动锁定

## 背景

ADR-0076 把窄屏会话栏改成抽屉，只做了「打开把焦点移到关闭按钮、关闭还给菜单按钮」，
没有焦点陷阱，也没有锁定背景滚动；键盘用户按 Tab 仍会走到遮罩后的标题栏和消息区，
移动端抽屉打开时背景仍可能滚动。这两项在 ADR-0076 的「待定」里明确留给了移动端专项。

## 备选

| 方案 | 结论 |
|---|---|
| 维持 ADR-0076 的边界，不做 | 否决：键盘用户仍会离开抽屉，移动端背景可滚动 |
| 引入 Radix/Headless UI Dialog | 否决：为一个抽屉新增依赖；ADR-0008 要求组件走 shadcn，但当前用不到完整 Dialog |
| 浏览器原生 `<dialog>` | 否决：要改 DOM 结构与样式，且与非模态侧栏共用同一组件时语义别扭 |
| 手写最小焦点陷阱 + `overflow: hidden` | 采纳：逻辑可抽成纯函数测试，不新增依赖 |

## 决策

1. `mobileOpen` 时把焦点移到抽屉的关闭按钮；关闭时由 ChatPage 还给标题栏菜单按钮
   （焦点归还已在 ADR-0076 实现）。
2. 在 `SessionList` 内监听 `Tab`/`Shift+Tab`：焦点到最后一个可聚焦元素后回到第一个，
   Shift+Tab 从第一个回到最后一个；焦点在抽屉外时拉回第一个/最后一个。
3. 焦点循环逻辑抽成纯函数 `nextFocusTarget(elements, active, shift)`，用 4 条单测覆盖
   向前/向后循环、焦点在外部、正常移动与空列表。
4. `mobileOpen` 时给 `document.body` 设 `overflow: hidden`，关闭或卸载时恢复原值。
5. 抽屉在窄屏用 `role="dialog"` + `aria-modal="true"`；≥640px 或关闭时不设该 role。
   遮罩按钮 `tabIndex={-1}`，只负责点击关闭，不进入 Tab 顺序。
6. 窗口变宽到 ≥640px 时通过 `matchMedia('(max-width: 639px)')` 的 change 事件关闭抽屉，
   避免桌面端残留遮罩状态、滚动锁定和对话框语义。
7. 不引入依赖、不做滑动关闭/动画、不锁主内容区的 `inert`（焦点陷阱已经阻止 Tab 离开）；
   仍不处理屏幕阅读器虚拟光标的背景遍历。

## 后果

- 键盘用户打开抽屉后 Tab 被限制在抽屉内，Escape/遮罩/X 关闭后焦点回到菜单按钮。
- 抽屉打开时背景页面不再滚动；关闭或窗口变宽自动恢复。
- 窄屏抽屉有 `role="dialog"` 和 `aria-modal`，辅助技术能识别为模态层。
- 焦点陷阱只在 `mobileOpen` 时启用，桌面侧栏不受影响。
- 没有引入依赖；循环逻辑有纯函数单测，但 DOM 查询、滚动锁定和 resize 关闭仍靠人工验收。
- 仍没有滑动关闭、过渡动画、背景虚拟光标隔离；这些留待移动端专项。
