# ADR-0086：置顶审计按日期范围过滤

## 背景

置顶审计已支持 `user_id`、`session_id`、`action` 过滤、游标分页、保留清理与 CSV 导出
（ADR-0081～0085）。但列表与导出都没有时间范围：交接、事故复盘或周报需要「某几天」
的置顶/取消置顶记录时，只能按最新记录逐页翻，365 天保留期内的早期记录实际不可达。

审计表已有 `created_at` 索引，前端也有 `PinAuditPage`；本 ADR 只增加日期过滤，不新增表
或迁移。

## 备选方案

| 方案 | 结论 |
|---|---|
| 前端对已加载行做日期过滤 | 否决：只能过滤当前页，无法访问未加载的历史 |
| 只提供一个日期端点（起始或结束） | 否决：语义不完整，仍需另一个参数才能表达窗口 |
| 按 `offset` 分页 | 否决：与已有 keyset 游标冲突，翻页期间新增记录会重复/跳过 |
| 不限制跨度 | 否决：保留期只有 365 天，允许任意跨度只会产生无效查询 |
| 详情表/物化表 | 否决：当前数据量不需要，索引已足够 |

## 决策

1. **参数与语义**：`GET /admin/session-pins` 与 `/export` 增加
   `created_from`/`created_to`（`YYYY-MM-DD`，UTC 自然日闭区间）。两端必须同时提供，
   否则 422 `INVALID_RANGE`；`from > to`、`to = 9999-12-31` 或跨度超过 365 天同样 422。
2. **内部半开窗口**：`created_from` 取当天 `00:00:00Z`，`created_to` 取次日
   `00:00:00Z`；store 用 `created_at >= after AND created_at < before`，避免
   `23:59:59.999999` 的边界歧义。
3. **列表与导出同口径**：导出不接收 cursor/limit，但与列表共享同一组过滤参数；
   导出仍是同步的、最多 5000 行的快照。
4. **游标绑定**：游标仍为 `{t,i,f?}`；`f` 是过滤条件（含日期范围）的 SHA-256 前
   16 位，不存原始日期。带日期范围时 `f` 变化；换范围复用旧游标返回 400
   `INVALID_CURSOR`。无日期范围的旧游标保持兼容。
5. **无迁移**：复用 `idx_session_pin_audits_time`，不新增索引；分页仍按
   `(created_at, id)` 倒序。
6. **前端**：`PinAuditPage` 增加两个 `type=date` 输入；应用前校验两端/顺序/365 天，
   错误显示在表单下方；清除同时清日期。导出使用**已应用**过滤，不读取输入草稿。
7. 不做：预设快捷日期、可配置时区、统计/按日趋势、导出下载审计、异步导出。

## 后果

- 列表/导出只能查最近 365 天内的窗口；恰好 365 天（含两端）允许。
- `created_to=9999-12-31` 被拒绝，避免次日加一天溢出。
- 日期范围与列表过滤、游标绑定；翻页期间新记录仍可能造成重复/跳过，与已有审计分页
  的边界一致。
- 旧后端会忽略 `created_from`/`created_to` 并返回未过滤结果，滚动升级需前后端同版本；
  旧前端不发送日期参数不受影响。
- 日期范围是服务端 UTC 自然日，用户浏览器时区不参与；与审计表 `created_at` 的
  UTC 存储一致。

## 待定

- 是否提供「近 7/30/90 天」快捷预设并记住上次选择。
- 是否支持可配置展示时区（当前 UTC 自然日）。
- 是否增加按日统计、总数、异步导出与下载审计。
