## 与 v1 的差别

- `mt-topic-shift-expense` 从诊断项**转正**为切换用例：ADR-0025 修好了「那 + 新话题」
  被上一轮稀释的问题，它现在必须命中《差旅报销流程》且不得引用保修文档；
- 新增 3 条切换用例（会议室 / 蓝屏 / VPN）：同一句追问在旧行为下都会答上一轮话题，
  其中「那VPN怎么连」在打印机之后最典型——合并检索词后打印机文档 0.916，VPN 只剩 0.72；
- 新增 2 条**守卫**指代用例（「那怎么申请」「那流程是什么」）：单独检索也能捞到文档，
  但多篇分数咬在一起，原句并没有点到哪一篇，必须继续用上一轮上下文——防止「原句优先」
  过度触发；
- 诊断项换成「那公司年会抽奖怎么规定」：**没点名任何文档**的新话题仍会被上一轮稀释，
  这是 ADR-0025 未覆盖的边界（要修得让模型改写查询）。

两条条件缺一不可，见 [ADR-0025](../decisions/0025-followup-original-first.md)。

## 口径与局限

- **只判最后一轮**：前面的轮次负责铺上下文，setup 失败会让整条用例失败；
  追问轮要求引用命中标注文档（文档级，不看段落）。
- **coref 的隔离对照**：同一句追问在空会话单独再跑一次，不得命中同一篇文档。
  只有对照成立，这次命中才能归因于上一轮上下文。
- **shift 的前提**：同一句追问在空会话必须命中所列文档。它守的是用例档位——
  如果单独提问都命不中，这句话其实是追问，写成 shift 会让 `shift_acc` 虚高。
- **只判命中，不判精度**：追问轮多引一篇无关文档不扣分（多余引用归主集 `cite_acc`）；
  `mt-vpn-err502` 同时引用了打印机文档，本集仍算解对。`shift_acc` 另外要求不含
  上一轮话题的文档，但不会因为多引第三篇无关文档而失败。
- **样本内**：16 条参与过追问启发式与分差阈值的标定，100% 不代表盲测泛化。
- **只覆盖被启发式判定为追问的句子**（≤ 30 字 + 指代词/承接词）；启发式漏判的追问
  不在这里，它们的表现仍是单轮行为。
- **多一次检索**：追问会先按原句检索一次（点不出具体文档才再检索合并句），
  mock 内存索引下可以忽略；真实嵌入服务下这条路径的延迟未做基准。
- mock 模式没有 LLM：历史只影响检索词与选句；真实模型的指代解析收益需要配置
  provider 后另跑。
- 诊断项 `mt-topic-shift-unnamed` 观测的是 ADR-0025 仍未覆盖的边界：新话题如果没有
  点名语料里的任何文档，话题头匹配不到标题，仍会拼上文并被上一轮带偏。
- 抽取式回答挑错句（例如 ERR-502 追问没给出"重置密码"）属于 `answer_acc` 的问题
  （docs/08 §2.1），本集不拿它冒充指代指标；答案断言只在「上下文选对了才能给出
  这个结论」时加。
- 复跑会覆盖 `server/eval-reports/multiturn-*.md`（该目录不入库），本文件是提交时的基线。
