# ADR-0045：运行过程筛选与耗时聚合

- 状态：已采纳（W6 后补）
- 日期：2026-11-13
- 相关：[ADR-0035](0035-run-timeline-replay.md)（运行过程回放）、[ADR-0036](0036-session-detail-batch.md)（批量会话详情）、[ADR-0044](0044-timeline-payload-cap.md)（载荷上限）

## 1. 背景

运行过程（ADR-0035）最多回放 20 项工具调用与审批。项数有上限，但**查看没有结构**：
工具与审批按 `seq` 混排，失败项和慢调用散在 JSON 里，用户想知道「这轮为什么慢/哪一步失败」
只能逐条展开。单条载荷已有上限（ADR-0044），剩下的是**可读性**问题，不是传输问题。

ADR-0035 的「待定」里一直写着「运行过程的搜索/筛选（按工具名、状态）与耗时聚合」。
时间线数据里已有 `kind`、`tool`、`status`、`duration_ms`，批量详情（ADR-0036）也已把这些
字段一次带到浏览器，客户端不需要额外请求就能做筛选与汇总。

## 2. 备选方案

| 方案 | 结论 |
|---|---|
| 服务端加 `?kind=&tool=` 查询参数 | 否：筛选只影响展示，第二次请求换来的只是同一批 20 项，契约还会多一组参数 |
| 新开「运行分析」接口 | 否：v1 只有 20 项，不值得为新页面/新索引建一层聚合 |
| 把筛选状态持久化到 URL/localStorage | 否：运行过程是单条回答的临时视图，刷新后保留筛选反而容易误解 |
| 纯客户端筛选 + 汇总（采纳） | 是：无契约变化、无迁移，纯函数可测，20 项的计算量可忽略 |
| 跨 run 的工具耗时统计 | 留到后续：那是成本/性能看板的事，不是单条回答的解释 |

## 3. 决策

1. **只在客户端做**：新增 `web/src/features/chat/timelineView.ts`，提供
   `summarizeTimeline`、`filterTimeline`、`formatDuration` 三个纯函数；
   不改 `GET /runs/{id}`、批量详情接口、服务端时间线投影，无迁移。
2. **筛选维度保持少而明确**：类型「全部 / 工具 / 审批 / 异常」+ 工具名子串（大小写不敏感）。
   两个条件同时生效；不做多选状态、不做正则、不做保存。
3. **「异常」的口径**：工具 `error` / `timeout` / `denied`，审批 `rejected` / `expired`；
   `pending`、`running`、`requires_approval` 不算异常（是过程，不是失败）。
   `truncated` 是展示裁剪，不是失败，不进入异常计数。
4. **汇总口径**：工具数、审批数、工具耗时之和、最慢工具（工具名 + 毫秒）、异常数。
   耗时只累加带 `duration_ms` 的工具结果；审批等待时间随后由 ADR-0046 单独展示，
   仍不计入工具耗时之和，也不参与「最慢」。
   缺少 `duration_ms` 的项不计入总和，也不参与「最慢」。
5. **展示位置**：汇总放在 `<summary>` 行（收起时也能看到「耗时 1.2s」），
   筛选条与「最慢」提示放在展开后的顶部；筛选后没有匹配项时显示「没有匹配的运行过程。」
6. **时间格式**：小于 1 秒用 `ms`，小于 1 分钟保留 1 位小数（`1.2s`，整数省略 `.0`），
   再长用 `Xm Ys`；59.95 秒以上直接进位到分钟（避免 `119999ms` 显示成 `1m 60s`）。
   只用于展示，不参与任何判定。
7. **不做**：服务端筛选/分页、跨 run 聚合、筛选状态持久化、导出、按状态多选、
   「仅看有耗时」等二级过滤。时间线仍最多 20 项，条数上限不变。

## 4. 后果

- 用户不展开也能看到总耗时；展开后可以只看工具、只看审批或只看异常，长 JSON 不再需要逐条翻。
- 筛选只影响当前回答的展示，不改变 `Timeline` 的数据来源；关闭折叠区/切换会话即重置。
- 「异常」是展示口径，不是新的状态机；`status` 的原始语义仍以事件为准。
- 耗时之和只是工具执行时间之和，不能当端到端延迟；同一工具多次调用会重复累计。
- 20 项以内筛选开销可忽略；如果未来放宽条数上限，需要重新评估是否改为服务端筛选。
- 无 SQL/迁移/接口变化，历史 run 重新打开也直接生效。

## 6. 待定

- 是否增加按状态多选（例如只看 `timeout`）与文本搜索参数/结果的全文。
- 是否把「最慢工具」做成跨 run 的 Top 列表（成本/性能看板，而非单条回答）。
- 筛选状态是否需要在同一条回答内跨展开保持（当前组件卸载即重置）。
- 审批等待时长：✅ 已由 [ADR-0046](0046-approval-wait.md) 实现（按 `approval.required` / `approval.resolved` 事件的 `ts` 差值，只对已决议项展示）；仍不计入工具耗时汇总与「最慢」。
- 20 项上限放宽后，筛选是否要下沉到服务端。
