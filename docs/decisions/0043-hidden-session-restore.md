# ADR-0043：已移除会话的查看与恢复

- 状态：已采纳
- 日期：2026-11-12
- 关联：[ADR-0030](0030-session-list.md)（会话列表）、[ADR-0033](0033-session-history-pagination.md)（分页）、[ADR-0041](0041-session-remove.md)（软移除）

## 1. 背景

ADR-0041 把「从列表移除」做成了软移除：只写 `hidden_sessions`，不删 `runs`/事件/审批。
这是正确的边界，但 v1 留了一个明显的缺口——移除之后没有任何入口能看见它，也没有恢复办法。
误点一次只能去数据库删行，或者等以后改代码。

ADR-0041 的「待定」第一条就是「恢复入口」。本轮补上它，同时保持两个前提：

- 恢复只是删 `hidden_sessions` 的一行，不重建/不删除任何 run、事件、审批或标题；
- 仍然没有管理员旁路：只列本人移除的会话，别人看不到，也恢复不了。

## 2. 备选方案

| 方案 | 结论 | 原因 |
|---|---|---|
| 移除时弹「已移除，撤销」toast | 否决 | 只能覆盖刚发生的操作；刷新/换设备后就没了，不能作为唯一入口 |
| 在 `GET /sessions` 加 `include_hidden=true` | 否决 | 把两种语义塞进一个列表，前端排序/分页/空态都要分叉；还容易误把隐藏会话带进搜索 |
| 单独的「回收站」页面 | 否决 | 为一个低频动作新增页面与路由；侧栏折叠区足够 |
| `GET /sessions/hidden` + `DELETE /sessions/{id}/hidden`，侧栏折叠区 | **采纳** | 复用会话投影与标题回退；无迁移；恢复就是删一行，语义最小 |

## 3. 决策

1. **没有新表、没有迁移**：`hidden_sessions` 已经在 ADR-0041 建好（迁移 `0017`）。
   恢复 = `DELETE FROM hidden_sessions WHERE user_id = ? AND session_id = ?`，不碰其他表。
2. **列表接口**：`GET /api/sessions/hidden`，只读本人，`limit` 1–50（默认 50），
   按 `hidden_at DESC, session_id DESC` 排序。标题口径与会话列表一致：自定义标题优先，
   否则最早一条非空 `input`；列表展示统一截到 60 字符。
3. **恢复接口**：`DELETE /api/sessions/{session_id}/hidden`。成功 204；
   没有移除过、或属于别人的会话，都返回 `404 {"detail":"session not found"}`（不泄露存在性）；
   `SQLAlchemyError` → 503 `DATABASE_UNAVAILABLE`。重复恢复按 404 处理（第二次已无行可删）。
4. **恢复后重新参与列表与搜索**：因为普通 `list_sessions` 只按 `hidden_sessions` 过滤，
   删掉行之后不需要任何缓存失效或重建；排序仍按最近一次 run 活动。
5. **`hidden_at` 保留第一次移除时间**：重复移除是幂等 no-op，不刷新时间；
   这样「移除于」显示的是用户第一次做这个动作的时间。
6. **前端**：侧栏底部加「已移除的会话」折叠区，**首次展开时才请求**，避免每次加载页面都多打一次接口。
   每条显示标题、轮数、移除时间与「恢复」按钮；恢复中禁用按钮；恢复成功后从折叠区移除并刷新
   普通列表（当前搜索词保持不变）。折叠区与普通列表共用同一个侧栏，不新增页面。
7. **隐藏会话后折叠区失效**：刚移除的会话应出现在「已移除」里；实现上在移除成功后关闭并清空折叠区，
   下次展开重新拉取，避免本地列表与服务器状态分叉。
8. **不做**：批量恢复、已移除列表内搜索/分页（默认最多 50 条足够）、管理员查看/恢复他人的会话、
   自动过期清理 `hidden_sessions`（表小，孤儿行问题与 ADR-0041 相同）。

## 4. 后果

- 误移除可以自助恢复，不需要改库；恢复不改变 run 数据与保留期，也不产生事件。
- 「已移除」是一个低频视图，默认收起；展开时才发请求，正常聊天路径没有额外开销。
- `GET /sessions/hidden` 在真实数据量下可能返回较多行，但 v1 限 50 条；更大的量需要分页
  （与普通会话列表不同，这里按 `hidden_at` 排序，游标语义要单独设计，列入待定）。
- 恢复只影响列表显示，不会让已过保留期的正文重新出现：`runs.citations`/正文仍按原时间清理。
- 仍然没有硬删除；「移除」与「删除数据」的区别继续由文案承担。

## 6. 待定

- 已移除列表的分页/搜索（目前最多 50 条、无游标）。
- 批量恢复/批量清理隐藏行。
- 管理员视角（当前明确不做：会话列表只读本人）。
- `hidden_sessions` 的孤儿行清理（run 行被手动删除时）。
- 恢复是否需要进入审计/事件流（当前与移除一样，是列表操作，不写事件）。
