# ADR-0085：置顶审计管理页

## 背景

置顶审计已经具备独立表、keyset 分页（ADR-0081/0082）、365 天保留清理
（ADR-0083）与 CSV 导出（ADR-0084），但只有管理员 HTTP 接口。交接、排障和
「这个会话为什么被置顶/取消」需要手工拼 `curl`、抄游标，管理端没有可用入口；
ADR-0081 的「待定」也明确列着前端管理页。

## 备选方案

| 方案 | 结论 |
|---|---|
| 在恢复审计页里混排列出 | 否决：两类审计字段与过滤条件不同，混排会把两种数据模型塞进一张表 |
| 只做 CSV 不做页面 | 否决：日常排障想看最近几条，不应先下载文件 |
| 页面直接按会话详情反查 | 否决：会话可能已被隐藏/清理，页面先给审计事实，不替用户做归属判断 |
| 复用列表/导出接口的只读页 | 采纳：后端已有完整过滤、分页、导出能力，本轮不新增接口 |
| 新增统计/按日趋势 | 暂缓：审计量小，先给列表与导出；统计留待真实需要 |

## 决策

1. 新增 ConsolePage 的「置顶审计」标签，路由 `/console/pins`，页面只读。
2. 过滤条件与接口一致：`user_id`、`session_id` 精确匹配（1–64），`action`
   `pin`/`unpin`；空值不下发；输入框 `maxLength=64`；日期范围由 ADR-0086 补上。
3. 列表每页 20 条，按 `(created_at, id)` 倒序；`next_cursor` 存在时显示「加载
   更多」，不做页码/总数。
4. 表格四列：时间、用户、会话、动作；动作显示「置顶 / 取消置顶」，不展示
   `args` 或其他正文。
5. 应用/清除过滤时立即清空旧行与游标、失效在途列表与导出请求，避免旧数据在
   新过滤下闪现；重试复用当前过滤。
6. CSV 导出使用**已应用**的过滤条件（不读取输入框草稿），提示成功条数或
   「超过 5000 条已截断」；导出不改变列表状态。
7. 前端 API 客户端独立为 `web/src/api/pinAudits.ts`，不把置顶审计类型混入
   恢复审计模块；错误沿用统一 `ApiError` 文案。首屏失败只显示错误卡与
   「重试」，不叠加「还没有记录」空态；空态只在成功返回空结果时显示。
8. 无后端/迁移变更；旧后端缺字段时页面显示错误卡，不伪造成功。

## 后果

- 管理员可以在浏览器里完成过滤、翻页和导出，不必手工处理游标。
- 页面与接口同源，过滤/游标语义不会分叉；但列表与导出仍是两次独立查询，
  不做稳定快照，也不提供总数；按日统计已由 ADR-0087 补上。
- 页面只读，不提供编辑、删除或「按会话反查详情」；这些仍需后端能力。
- 过滤条件不持久化，刷新后回到全部记录；审计仍有 365 天保留上限。

- 前端 `tsc --noEmit`、`vitest` **117 tests / 25 files**、`oxlint` 0/0
  （88 files/231 rules）、`oxfmt --check` 96 files、`pnpm build` 通过

- 置顶审计 API 客户端测试覆盖过滤/游标查询串、无过滤导出、截断响应头。
- 后端未改，沿用默认 514+40 / PG 551+3 / Redis 554、ruff 200 / mypy 116。

## 待定

- 是否增加总数；当前只给最近记录与导出。按日统计已由 ADR-0087 实现。
- 是否支持从审计行跳到会话详情/运行回放。
- 是否把恢复审计与置顶审计合并成统一「审计中心」导航。
- 下载审计、导出异步化、防篡改链仍未做。
