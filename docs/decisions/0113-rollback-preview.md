# ADR-0113：工具配置回滚前展示差异预览

## 背景

ADR-0112 的回滚按钮只用 `window.confirm("将工具配置回滚到该变更发生前的状态？")`。
管理员看不到这次回滚会把启用状态和角色改回什么，确认框也不显示操作人/时间；误点会
直接写一条新配置，再回滚回来还要多一次写操作。ADR-0112 把「差异预览」留在待定。

## 备选方案

| 方案 | 取舍 |
|---|---|
| 保持 `window.confirm` | 实现最小，但无法展示 `before → after`，误操作成本高 |
| 把两个快照拼进 confirm 文案 | 不需要新组件，但角色列表可能很长、不可读，且无法排版 |
| 新增后端 preview 接口 | 能拿到执行瞬间的当前值，但多一次请求与契约，收益不足以抵消 |
| **独立确认 Dialog（采用）** | 用已有 `ToolChange.before/after` 展示目标与记录时状态；只在前端做 |

## 决策

1. 点「回滚」不再直接 `window.confirm`，而是打开 `RollbackPreviewDialog`。
2. Dialog 展示：工具名、该条变更时间、记录时的配置（`after`）、回滚目标（`before`），
   复用 `describeSnapshot`，`null` 显示为「代码默认」。
3. 明确提示：实际写入的 `before` 是执行瞬间读到的当前配置，可能与该记录快照不同
   （last-write-wins，ADR-0112）；回滚会新增记录，不删除原记录。
4. 只有点「确认回滚」才调用 `POST .../rollback`；取消/关闭不写。执行期间按钮显示
   「回滚中…」，失败在历史 Dialog 内提示，成功刷新列表与历史。
5. 不改后端、不加字段、无迁移；不预取当前配置，也不做批量差异或角色 diff 高亮。

## 后果

- 每次回滚多一次确认，但管理员能在写之前看到目标与记录时状态。
- 预览展示的是历史快照，不是执行瞬间的当前值；该差异由 Dialog 文案显式说明。- 提示写明「当前实例立即生效、多副本部署下最多 2 秒生效」，与工具配置覆盖的 2s 缓存一致。
- 仍不支持批量回滚/整次矩阵撤销；`source` 继续复用 `tool`。

## 验证

- `web/src/features/console/toolHistoryFormat.test.ts`：`describeSnapshot` 覆盖
  `null`、启用/禁用、角色继承/空角色/多角色。
- 前端 31 files / 157 tests、`tsc`、`oxlint`、`oxfmt --check`、`pnpm build` 通过。
- 后端未改，沿用默认 537+42 / PG 576+3 / PG+Redis 579。

## 待定

- 是否在 Dialog 内显示「执行瞬间的当前配置」（需要额外 preview 接口）。
- 是否给回滚加独立 `source="rollback"`，便于历史筛选。
