# ADR-0102：工具配置变更历史游标过期

## 背景

ADR-0100 给工具配置变更历史加了 keyset 游标：base64url JSON `{t,i,f}`，`f` 绑定工具名与
已应用筛选。当时明确把「游标是否需要过期」列为待定；游标只要筛选不变就一直可用，管理员
把历史 Dialog 放在后台数天后再点「加载更多」，仍会从旧位置继续翻页。

游标本身不含敏感数据，也不是权限凭证；但长期可复用的分页位置会让「当前视图」和「实际
时间」脱节，且服务端无法区分一次正常翻页和很久以前遗留的游标。这里只解决过期，不做
签名、加密或防篡改。

## 备选方案

| 方案 | 取舍 |
|---|---|
| 不过期 | 实现最小；旧游标在数据保留期内一直可用，视图可能停留在很久以前 |
| 签名 + 过期 | 能防伪造，但需要密钥管理/轮换；游标只由服务端生成，当前没有伪造威胁 |
| 显式时间戳 `e` + 固定 TTL（采纳） | 不引入密钥；过期后明确 400，前端可提示重新加载；实现仍是纯函数 |

## 决策

1. 游标 JSON 增加 `e`：Unix 秒，写入时间为签发时刻 + `TOOL_HISTORY_CURSOR_TTL_S`（1 小时）。
2. `_decode_tool_history_cursor` 校验 `e` 为整数；`e < now` 返回
   `400 {"code":"CURSOR_EXPIRED","message":"游标已过期，请重新加载"}`。
3. 缺 `e`、非整数（含 `1.5`、布尔值、过大指数解析出的 `inf`）、时区缺失、指纹不匹配、
   ID 非法仍统一 `400 INVALID_CURSOR`；旧版本签发的游标在部署后直接失效，不尝试兼容。
4. TTL 是代码常量，不提供环境变量；先观察真实使用，再决定是否可配。
5. 不做游标签名/HMAC/加密；过期不等于权限校验，接口仍先要求管理员。
6. 前端不自动重放请求：`useToolHistory` 的「加载更多」失败继续把错误放在
   `loadMoreError`，已加载列表保留；`CURSOR_EXPIRED` 时显示「重新加载」按钮，按已应用
   筛选重新取第一页（[ADR-0103](0103-tool-history-cursor-reload.md)），不自动重放。
7. 无表、无索引、无迁移；导出不使用游标，因此不受影响。

## 后果

- 正常翻页（1 小时内）无感；超过 1 小时的旧游标会失败一次，需要重新加载。
- 多副本部署不需要共享时钟之外的协调；各副本用本机 UTC 判断，TTL 有 1 小时余量。
- 部署新版本会让部署前签发的游标失效，这是可接受的短期分页状态。
- 错误码从单一 `INVALID_CURSOR` 变成两种：格式/筛选问题用 `INVALID_CURSOR`，时间问题用
  `CURSOR_EXPIRED`；客户端可据此提示「重新加载」。
- 仍不防伪造：拿到游标的人可以在有效期内继续翻页，但接口每次都校验管理员身份和筛选。

## 验证

- `server/tests/test_tool_history.py` 的过期游标用例：手工构造 `e=1` 的游标，断言
  `400 CURSOR_EXPIRED`；同一用例还覆盖缺 `e`、`e=1e309`（解析为 `inf`）与 `e=1.5`，
  断言 `INVALID_CURSOR`；既有分页/改筛选/非法游标用例继续覆盖 `INVALID_CURSOR`。
- 默认 533+42、PG 572+3、PG+Redis 575；ruff 208 / format 208 / mypy 119；前端 27 files /
  140 tests（ADR-0103 补 2 个错误码用例）。
- 详见 [ADR-0100](0100-tool-history-pagination.md)、[ADR-0101](0101-tool-history-filters.md)。

## 待定

- TTL 是否改为可配置（例如 15 分钟 / 24 小时）；
- 过期后是否在 Dialog 内提供「重新加载」快捷按钮，而不是要求关闭重开：已由
  [ADR-0103](0103-tool-history-cursor-reload.md) 补上；
- 是否把游标签名与过期一起做（当前明确不做）。
