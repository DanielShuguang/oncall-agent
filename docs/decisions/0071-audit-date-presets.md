# ADR-0071：审计日期范围快捷预设

- 状态：已采纳
- 日期：2026-11-15
- 相关：[ADR-0067](0067-session-restore-audit-date-range.md)

## 背景

会话恢复审计页已支持 UTC 起止日期（ADR-0067），但交接、事故复盘与月度对账
通常只需要「近 7 天」「上个月」这类常见窗口。每次手动填两个日期既慢，也容易
把起止填反或漏填一端，随后被服务端 422 拒绝。

## 备选方案

| 方案 | 结论 | 原因 |
|---|---|---|
| 后端新增 `preset=` 参数 | 否决 | 预设只是常见窗口的快捷方式，后端已有任意日期范围；新增参数会扩大契约 |
| 前端只放说明文案，让用户照着手填 | 否决 | 没有减少操作成本，日期仍会填错 |
| 引入日期选择器/日历库 | 否决 | 只为 5 个预设引入依赖不划算，现有 `<input type="date">` 已够用 |
| 纯前端按钮 + 纯函数计算 | 采纳 | 不改后端、不引依赖，逻辑可用固定 `now` 单测 |

## 决策

1. **纯前端能力**：不改 API、不改响应、不改游标，也不新增迁移。预设最终仍调用
   已有 `applyFilters`，与手填日期走同一条请求路径。
2. **UTC 自然日闭区间**：与 ADR-0067 完全一致；`from`/`to` 都是 `YYYY-MM-DD`，
   不做浏览器本地时区换算。
3. **五个预设**：
   - 近 7 天：含今天，即 `today - 6` 至 `today`；
   - 近 30 天：含今天，即 `today - 29` 至 `today`；
   - 近 90 天：含今天，即 `today - 89` 至 `today`；
   - 本月：本月 1 日至今天；
   - 上月：完整上一个 UTC 月（自动处理 28/29/30/31 天与闰年）。
4. **点击即应用**：快捷按钮直接调用 `applyFilters(range)`，不要求用户再点「筛选」；
   用户/会话输入框里的草稿值仍然保留，三者一起提交。
5. **纯函数、可注入时间**：`auditDatePresetRange(preset, now = new Date())` 不读全局
   时钟，测试固定 `now` 即可断言边界，不依赖运行日期。
6. **范围**：不做自定义预设、不记住上次选择、不做「本周」「上周」的本地时区版本；
   预设不绕过服务端最多 365 天与起止顺序校验。

## 后果

- 交接/复盘从「两次输入 + 点筛选」变成「一次点击」，且不会漏填一端。
- 页面仍以 UTC 标注；用户若在本地时区跨日操作，看到的仍是 UTC 口径。
- 「近 N 天」含今天，按 UTC 自然日闭区间计算；统计接口的 `days` 是从当前时刻
  往前滚动的 `N×24` 小时，两者意图接近但不完全等价。「上月」是完整自然月，
  与「近 30 天」在月初/月末会得到不同结果，这是预期差异。
- 纯前端改动，不影响旧后端；旧后端仍会收到 `restored_from`/`restored_to`
  并忽略未知参数（ADR-0067 的版本边界仍成立）。

## 验证

- 前端：`tsc --noEmit`、**93 tests / 19 files**、`oxlint` 0/0（75 files/231 rules）、
  `oxfmt --check` 83 files、`pnpm format:check`、`pnpm build` 通过。
- 单测固定 `2026-03-15T12:00Z`：近 7 天 `2026-03-09`、近 30 天 `2026-02-14`、
  近 90 天 `2025-12-16`、本月 `03-01..03-15`、上月 `02-01..02-28`；
  另用 `2024-03-15` 覆盖闰年 2 月 `02-29`、`2026-01-15` 覆盖跨年 12 月、
  `2026-03-31` 覆盖 31 天月末，以及 `2026-03-03` 覆盖近 7 天跨月。
- 后端未改，沿用默认 **504+40**、Postgres **541+3**、Redis **544**；
  `ruff` 196 / `mypy` 114 files。

## 待定

1. 是否记住用户上次选择的预设；当前每次进入页面都从手填/空日期开始。
2. 是否增加「本周」「上周」；它们更贴近本地时区，而当前页面固定 UTC。
3. 是否把预设做成可配置项；当前五个覆盖交接与月度对账的常见场景。
