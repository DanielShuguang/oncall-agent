# ADR-0056：审批列表导出 CSV

## 背景

审批中心已经有待办/已办、状态、工具/审批人/日期筛选和 keyset 翻页（ADR-0052 /
ADR-0053 / ADR-0054），但所有记录只能在页面里看。审计、交接和离线对账需要把
当前筛选结果带走；逐页截屏或复制表格既容易漏，也无法作为稳定格式交给 Excel。

导出不是分页的替代品：它要的是一次性、可重复、字段稳定的快照。审批数据里有
工具参数（`args`）和审批理由，前者可能含身份、主机名等敏感值，不能默认进入
表格；后者是审批人自己填写的处置依据，属于审批元数据，授权用户可见。

## 备选方案

| 方案 | 否决原因 |
|---|---|
| 前端把已加载的页拼成 CSV | 只覆盖当前已加载的几十条，翻页/筛选后不完整，也没有稳定的全量顺序 |
| 新增异步导出任务 + 下载令牌 | 需要任务表/对象存储/轮询与清理，5000 条以内的小导出不值得引入一套后台作业 |
| 返回一次性签名 URL | 仍要新增签名密钥、过期与下载审计；当前规模直接用带 Bearer 的同步请求更简单 |
| 导出全部行，不设上限 | 审批积压无上限，单次请求可能拉爆内存/连接；必须给同步请求一个硬上限 |
| 把 `args` 也放进 CSV | 参数里可能有 token、主机名、工单正文；导出面比页面更难控制，默认不导出 |
| 复用统计接口导出聚合数据 | 统计是聚合值，不能回答「哪几条审批、谁批的」；逐条导出需要独立接口 |

## 决策

1. **新增 `GET /approvals/export`，同步返回 CSV**。查询参数与列表一致：
   `status`、`tool`、`resolved_by`、`resolved_from`、`resolved_to`；不接收
   `cursor`/`limit`。排序沿用列表：待办按 `(expires_at, created_at, approval_id)`
   升序，已办按 `(resolved_at, approval_id)` 倒序；筛选只对已办生效，待办带筛选
   仍返回 `422 INVALID_FILTER`。
2. **最多导出 5000 条，超出显式截断**。内部取 `MAX_EXPORT_ROWS + 1` 判断是否
   还有更多；响应头 `X-Export-Count` 是实际行数，`X-Export-Truncated` 是
   `true|false`。截断时保留当前排序的前 5000 条，不静默假装完整；需要更全的
   数据应缩小筛选或等后续异步导出。
3. **只导出审批元数据，不导出 `args`**。列为
   `approval_id, run_id, call_id, tool, risk_level, status, requested_by,
   resolved_by, scope, created_at, expires_at, resolved_at, reason`。工具参数
   留在页面/审批详情里按权限查看；CSV 面向审计与对账，不承担参数备份职责。
4. **CSV 兼容 Excel，并挡公式注入**。UTF-8 BOM + CRLF；时间统一 ISO 8601
   （UTC）；以 `= + - @ \t \r` 开头的单元格前置单引号，避免 Excel/WPS 把审批
   理由当公式执行。逗号、引号、换行由标准 CSV writer 转义。
5. **导出走与列表相同的身份范围**。审批人可导出全部（仍受筛选约束）；普通员工
   只能导出自己发起的。导出不新增权限，也不因为「导出」绕过 `requested_by`。
   响应带 `Cache-Control: no-store` 与 `Content-Disposition: attachment`。
6. **前端用带 Bearer 的 fetch 下载 Blob**。不做 `window.open`/`<a href>` 直链，
   否则浏览器不会带 `Authorization`；按钮使用当前已应用的 `status` + `filters`，
   成功后提示导出行数，截断时提示「已导出前 5000 条」。导出失败不清空列表，
   只在按钮旁显示错误。

## 后果

- 审计/交接可以拿到稳定字段的 CSV；不需要为一次性导出引入后台任务或对象存储。
- 5000 条是硬边界；大量数据只能缩小筛选范围，或等未来的异步导出。CSV 本身不带
  「被截断」标记，直接调用 API 的客户端必须读 `X-Export-Truncated` 响应头。
- 前置单引号会改变以 `-` 等字符开头的理由文本；这是为了不让表格执行公式，属于
  有意的格式损失。需要原样文本时应从页面/API 读取。
- 不导出 `args` 会让「参数快照」无法从 CSV 还原；审批详情页仍保留完整参数，
  CSV 不是备份格式。
- 一次查询最多加载 5001 条审批（含未导出的 `args`），上限约束了内存与数据库压力；
  查询期间的新决议不会进入本次快照，也没有下载审计。
- 无迁移、无新索引；复用列表的排序与筛选索引。

## 验证

- 默认 `pytest`：**487 passed + 40 skipped**；真实 Postgres：**524 passed + 3
  skipped**；Postgres + Redis：**527 passed**。
- 契约用例覆盖：CSV 表头与列顺序、逗号/引号/换行转义、公式注入前置单引号、
  `args` 不出现在响应、审批人/普通员工身份范围、工具筛选、`X-Export-*` 头、
  UTF-8 BOM、5001 行截断、待办筛选 422。
- `ruff check` / `ruff format --check`（188 files）/ `mypy app`（110 files）通过；
  前端 `tsc`、**80 tests / 16 files**、`oxlint` 0/0（68 files）、`oxfmt --check`
  76 files、`pnpm build` 通过。无迁移。

## 待定

- 统计聚合的 CSV 导出（与逐条导出是不同数据形状）。
- 超过 5000 条时的异步导出、对象存储与下载审计。
- 是否允许管理员跨用户导出；当前仍按请求者身份过滤。
- 是否把审批参数 `args` 作为可选的第二张表/压缩包导出。
- 导出文件的保留期、水印与下载审计。
