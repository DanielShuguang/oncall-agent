# ADR-0135：已办审批筛选按浏览器记住

## 背景

审批中心只有「已办」支持工具/审批人/决议日期筛选（ADR-0054）。这些筛选只存在于
`ApprovalsPage` 的内存状态，刷新页面或切走再回来就回到空筛选；同一页的统计窗口
（ADR-0127）和分组（ADR-0128）已经按浏览器记住，筛选却不记，行为不一致。

待办没有筛选入口，也不应该继承已办筛选：把已办的工具/审批人筛选带到待办会隐藏
待处理项。因此记忆必须只作用于已办。

## 备选方案

| 方案 | 结论 |
|---|---|
| 不记，保持现状 | 刷新即丢，与统计窗口/分组不一致 |
| 记住状态（pending/approved/...） | 状态是默认入口，记住会改变用户打开页面看到的列表；不做 |
| 每个状态各记一份筛选 | 待办无筛选；已办三个状态共用一组工具/审批人/日期更简单 |
| 记住已办筛选，进入待办时只用空筛选、不删记忆 | 采纳 |

## 决策

1. **只记已办筛选**：`tool`、`resolvedBy`、`resolvedFrom`、`resolvedTo`，统一存
   `localStorage` key `oncall.approval-filters.v1`。
2. **不记状态**：页面仍默认打开待办；待办始终使用空筛选，不读取记忆里的值。
3. **切到已办时恢复**：从待办切到任一已办状态时读取记忆并应用；三个已办状态之间
   切换保留当前筛选，不重置。
4. **切回待办不删记忆**：只把内存筛选清空，避免待办列表被已办筛选影响；下次再进
   已办仍能恢复。用户点「清除」或空筛选提交时才删除 key。
5. **写入时机**：点「筛选」应用后写 key；空筛选时删 key；损坏 JSON、存储不可用、
   字段类型不对、id 超 64 字符、日期不是 `YYYY-MM-DD` 时忽略该字段，不虚构值。
6. **切换账号清理**：`clearLocalPreferences` 同时删除该 key，避免上一位用户的审批
   人筛选留给下一位。
7. **不做**：不把筛选写进 URL/后端、不做跨设备同步、不记待办筛选、不新增 API 或
   迁移。

## 后果

- 刷新后仍默认进待办；切到已办时恢复上次已办筛选，符合「待办不筛、已办可筛」的
  既有权限与交互。
- 只有浏览器本地状态；换浏览器/设备不同步。清除浏览器数据后回空筛选。
- 已办筛选与游标绑定（ADR-0054）不变；改筛选仍从第一页重新加载。
