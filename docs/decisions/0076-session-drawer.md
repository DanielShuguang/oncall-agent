# ADR-0076：窄屏会话栏改为抽屉

## 背景

桌面端会话页是「288px 会话侧栏 + 消息区」两栏。窄屏（<640px）当前直接把侧栏 `hidden`，
但标题栏没有替代入口，用户无法查看、切换或新建会话，只能刷新回空态。README「已知局限」
也明确写了「窄屏隐藏会话栏，暂没有抽屉入口」。

## 备选

| 方案 | 结论 |
|---|---|
| 窄屏也常驻侧栏 | 否决：288px 会挤掉消息区，输入框和表格不可用 |
| 底部弹出会话列表 | 否决：会话多时高度不足，搜索/批量管理操作拥挤 |
| 单独的 `/sessions` 路由 | 否决：切换会话要离开对话页，丢失当前运行时上下文 |
| 抽屉（overlay + 侧栏） | 采纳：复用同一 `SessionList`，不复制列表/请求状态 |

## 决策

1. `<640px` 时侧栏默认隐藏，标题栏左侧显示菜单按钮（`aria-controls="session-list"`、
   `aria-expanded`）打开抽屉；≥640px 恢复常驻侧栏，菜单按钮隐藏。
2. 抽屉复用同一个 `SessionList`，只切换外层定位/可见性，不复制组件、不重复拉取会话。
3. 关闭方式：点遮罩、按 Escape、选择会话、点新会话；打开后不改变当前 `sessionId`。
4. 抽屉使用 `fixed` 定位、半透明遮罩和阴影；桌面端点开后若窗口变宽，CSS 恢复为常驻侧栏。
5. 不引入路由参数、不持久化抽屉开合状态；刷新后回到默认收起。
6. 不做手势滑动、焦点陷阱、动画；这些留待后续移动端专项。

## 后果

- 窄屏可访问全部会话能力（切换、搜索、置顶、改名、移除、批量管理、已移除恢复）。
- 因为只渲染一份 `SessionList`，列表请求、勾选、批量和折叠区状态不会出现两份。
- 未做焦点陷阱：抽屉打开时 Tab 仍可移到遮罩后的页面；键盘用户依赖 Escape 关闭。
- 抽屉状态不持久化，刷新后收起；也没有滑动关闭。
- 不是独立路由，深链到某个会话仍依赖应用内状态。
