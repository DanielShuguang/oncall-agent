# ADR-0111：恢复审计统计卡标注未恢复置顶数

## 背景

ADR-0108 让恢复已移除会话时按置顶容量尽力恢复，ADR-0109 在每条审计行记录
`repinned_count`，ADR-0110 在统计卡增加窗口内 `repinned` 汇总。但管理员看到
「恢复会话 10、恢复置顶 6」时，仍要自己相减才知道有 4 个会话没有恢复置顶，也不清楚
这是原本就没置顶还是容量不足。

## 备选方案

| 方案 | 取舍 |
|---|---|
| 服务端新增 `unrepinned` 字段 | 可由已有 `sessions - repinned` 推导；加字段等于让同一个事实有两个来源 |
| 直接提示「容量不足」 | 不准确：原本未置顶的会话也会计入差值；当前数据没有记录原置顶意图 |
| 不做 | ADR-0110 已把差值作为待定，管理员仍要手算 |

## 决策

1. 前端新增纯函数 `countUnrestoredPins(stats)`：`max(0, sessions - repinned)`，不改 API、不加迁移。
2. 恢复审计统计卡在差值大于 0 时显示一行：
   「其中 N 个恢复会话未恢复置顶（原本未置顶或容量不足，ADR-0108/0109）」。
3. 只标注数量，不判断原因，不把差值称为「失败」。
4. 差值不大于 0 时不渲染；旧的异常数据（理论上 `repinned > sessions`）按 0 兜底，不显示负数。
5. 不做比例条、日趋势、按用户拆分；这些需要新的统计口径，另开 ADR。

## 后果

- 管理员不用手算，但仍需逐行查看才能知道具体哪些会话没有置顶。
- 文案明确保留了两种原因，不会把「原本未置顶」误报成容量问题。
- 纯前端改动，后端与 API 契约不变；旧后端缺少 `repinned` 时不在本 ADR 的兼容范围内
  （前后端同版本部署）。

## 验证

- `web/src/features/console/restoreAuditStats.test.ts`：差值、全置顶、异常大值 3 个用例。
- 前端 30 files / 152 tests、`tsc --noEmit`、`oxlint 0/0`、`oxfmt --check` 149 files、
  `pnpm build` 2945 modules。
- 后端未改，沿用默认 535+42 / PG 574+3 / PG+Redis 577。

## 待定

- 是否增加「恢复置顶 / 恢复会话」比例；
- 是否在详情表按未置顶筛选；
- 容量不足时是否由后端记录明确原因。
