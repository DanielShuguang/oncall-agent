# ADR-0054：已办审批筛选与游标绑定

## 背景

ADR-0053 把已办审批改成按 `resolved_at` 倒序，解决了「最近的决议看不见」的问题，
但审批人想找某次操作仍然只能一页页翻：`GET /approvals` 没有工具、审批人、决议日期
参数，前端也没有筛选入口。审批中心的统计已经有「按工具/审批人」分组（ADR-0051），
但那是聚合，不能直接跳到某一条记录。

本 ADR 只解决**已办列表的筛选**，不碰待办：待办已经有到期顺序，按工具/审批人筛
待办的需求没有出现过，贸然加参数会让「最急的在前」和「只看某个工具」两个目标
混在一起。

## 备选方案

| 方案 | 否决原因 |
|---|---|
| 前端在当前页内过滤 | 只能过滤已加载的 50 条，越翻页越错；用户会以为「没有这条」 |
| 只加筛选参数、不绑定游标 | 换筛选后复用旧游标会从错误位置继续，静默漏数据 |
| 用 offset/页码做筛选分页 | 与现有 keyset 游标体系冲突；翻页期间新决议会整体错位 |
| 新增 `/approvals/search` 专用端点 | 身份过滤、审批人可见范围、游标逻辑都要复制一份，后续容易漂移 |
| 给 `tool_name` / `resolved_by` 各加索引 | 当前审批表是人工处理量级，工具/审批人区分度低，先按残余过滤；等真实查询计划再补 |

## 决策

1. **只对已办开放筛选**。`tool`、`resolved_by`、`resolved_from`、`resolved_to`
   任一出现且 `status=pending` 时返回 `422 INVALID_FILTER`；待办列表保持原样。
   `status` 缺省仍是 `pending`，所以「不带 status 只带筛选」也会被拒绝，调用方
   必须显式写 `status=approved|rejected|expired`。
2. **工具/审批人精确匹配，日期按 UTC 自然日半开区间**。`tool` 去空白后 1–100
   字符，`resolved_by` 去空白后 1–64 字符；`resolved_from` 含当天 00:00，
   `resolved_to` 不含当天（内部转成次日 00:00）。`resolved_from > resolved_to`
   返回 `422 INVALID_RANGE`；`resolved_to=9999-12-31` 无法安全加一天，也返回
   `422 INVALID_RANGE`。日期参数只接受 `YYYY-MM-DD`，不做时区换算。
3. **不新增索引、不改排序**。继续使用 `idx_approvals_resolved` 的
   `(status, resolved_at, id)` 部分索引，工具/审批人作为索引后的残余过滤；数据量
   变大后再根据真实执行计划决定是否补 `(status, tool_name, resolved_at)` 一类的
   索引。不加迁移，避免为尚未验证的查询模式先付写入成本。
4. **游标绑定筛选条件**。已办游标在 `{s,r,i}` 基础上增加可选的 `f`：
   把筛选条件按固定键 `{"t","b","f","u"}` 做 canonical JSON（键排序、无空格）
   后取 SHA-256 前 16 个 hex。没有筛选时仍返回 `{s,r,i}`，旧游标继续可用；
   有筛选时解码必须同时匹配 `s` 和 `f`，否则 `400 INVALID_CURSOR`。这样换工具、
   换审批人、改日期范围后旧游标不会静默续翻。
5. **前端只给已办显示筛选卡**。工具、审批人、决议开始/结束日期四个输入 +
   「筛选 / 清除」；点筛选先做 `from > to` 的客户端提示，再重置列表和游标；
   切换状态时清空筛选与输入，避免把已办条件带进待办。筛选条件变化一律从第一页
   重新加载，不保留「每个状态一套筛选」。
6. **身份与可见性不变**。筛选叠加在现有 `requested_by` 可见范围之上：审批人看
   全部，普通员工仍只看自己发起的审批；筛选不能绕过这条边界。

## 后果

- 筛选变化后旧游标返回 400 是预期行为，前端会重新拉第一页；直接调 API 的客户端
  需要把 `next_cursor` 和本次筛选一起保存。
- `f` 只是指纹，不是签名：客户端可以伪造一个合法游标，但服务端仍按当前身份过滤，
  伪造游标最多让调用方从任意时间点开始翻页，不能越权。游标签名/过期仍留待定。
- 工具/审批人没有独立索引，审批表很大时这两个条件会退化为索引后过滤；这是刻意
  推迟的优化，等有真实数据量再补。
- 翻页期间新增的决议可能让后续页重复或跳过；筛选不改变 keyset 分页的这个固有
  语义，刷新即回第一页。
- 日期只有 UTC 自然日，没有「本地时区」选项；跨时区审批人看到的日界线是 UTC。

## 验证

- 默认 `pytest`：**485 passed + 40 skipped**；真实 Postgres：**522 passed + 3
  skipped**；Postgres + Redis：**525 passed**。
- 新增用例：内存筛选（工具/审批人/日期组合）、API 筛选 + 游标换筛选 400 +
  待办带筛选 422 + 起止倒置 422、PG 筛选；前端 `listApprovals` 查询参数。
- `ruff check` / `ruff format --check`（188 files）/ `mypy app`（110 files）通过；
  前端 `tsc`、**75 tests / 15 files**、`oxlint` 0/0、`oxfmt --check` 74 files、
  `pnpm build` 通过。无迁移。

## 待定

- 按工具/审批人建索引，以及「已办总数 / 跳页 / 导出」。
- 游标签名或过期，防止客户端长期保存旧位置。
- 跨时区的「决议日期」口径；当前固定 UTC。
- 待办是否也需要按工具/审批人筛选；目前没有需求，且会与到期紧迫度排序混用。
