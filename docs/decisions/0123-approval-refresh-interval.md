# 0123 审批统计自动刷新间隔可配置

## 背景

ADR-0115 把审批统计的自动刷新固定为 30 秒，ADR-0116 增加了开关与失败提示，ADR-0122 让开关持久化。但刷新间隔仍写死：值班页面希望更频繁，低峰巡检希望更省请求，只能修改代码。

本 ADR 让间隔成为浏览器偏好：15/30/60 秒三档，默认 30 秒；不改变页面可见时才轮询、失败保留旧统计、暂停后不提示等既有语义。

## 备选方案

| 方案 | 不采纳原因 |
|---|---|
| 在服务端配置 | 这是单个浏览器页面的查看习惯，不是部署级策略；服务端配置会让所有管理员共用同一节奏 |
| 自由输入秒数 | 需要额外边界校验与「太小打爆接口」的防护；三档已覆盖值班/日常/低峰 |
| 与开关共用 key 存 JSON | 现有 key 是 `on`/`off`，改格式需要兼容旧值；独立 key 更简单，也便于账号切换时分别清理 |
| 不持久化（仅当前标签页） | 刷新页面即回到 30 秒，用户每次都要重设，和 ADR-0122 的开关体验不一致 |

## 决策

1. 存储 key 为 `oncall.approval-stats-refresh-interval.v1`，值为 `15`/`30`/`60`。
2. 读取时只接受三档；缺失、损坏、越界、存储不可用一律回退 30 秒。
3. 切换账号时 `clearLocalPreferences` 删除该 key，和审批统计开关、审计偏好一起清理。
4. 页面保存 `refreshIntervalSec` 状态；`setInterval` 使用 `refreshIntervalSec * 1000`，修改后 effect 重启定时器。
5. 关闭自动刷新时不启动定时器；重新打开仍立即补拉一次，之后按当前间隔轮询。
6. 文案只显示当前间隔，不承诺服务端推送；不改变 30 秒默认值。

## 后果

- 用户可以把值班页调到 15 秒，也可以把低峰页调到 60 秒；默认行为不变。
- 三档是固定的，不能输入任意秒数；以后若要加档，需要同时改选项、测试与文案。
- 偏好只在本浏览器生效，不跨设备、不跨账号；切换账号会清空。
- 修改间隔只重启本地定时器，不立即触发请求；下一次到期才按新间隔执行。

## 验证

- `approvalStatsRefresh` 新增读取/写入/清除用例：默认 30、写 60 读 60、`45`/损坏值回退 30、清除后回 30。
- `localPreferences` 断言切换账号会删除新 key。
- 前端：`tsc --noEmit`、`oxlint` 0/0、`oxfmt --check`、`pnpm test`、`pnpm build` 通过。
