# ADR-0084：置顶审计 CSV 导出

## 背景

置顶/取消置顶审计（ADR-0081）已经支持按用户、会话、动作过滤和 `(created_at, id)`
游标分页（ADR-0082），并按独立 365 天保留期清理（ADR-0083）。但管理员只能逐页浏览，
交接、对账、保留期前归档都需要一次性快照；现有的会话恢复审计导出只能导恢复操作，
不能代替置顶审计。

## 备选方案

| 方案 | 结论 | 原因 |
|---|---|---|
| 前端逐页拉取后拼 CSV | 否决 | 只覆盖已加载页，且把导出逻辑放到客户端 |
| 不设上限全量导出 | 否决 | 审计量随时间增长，同步请求可能长时间占用连接 |
| 异步导出任务 | 否决 | 需要任务队列/对象存储，当前部署形态没有 |
| 只导出汇总 | 否决 | 交接需要逐条记录，不是统计 |
| 复用会话恢复审计导出端点 | 否决 | 表、字段、过滤参数不同 |
| **同步导出 + 5000 行上限** | **采纳** | 与审批/恢复审计导出一致，简单可预期 |

## 决策

1. **端点**：`GET /admin/session-pins/export`，与列表相同的 `user_id`/`session_id`/
   `action` 过滤；不接收 `cursor`/`limit`。管理员权限与列表一致。
2. **上限**：最多 5000 条；取 5001 条判断是否截断，只输出前 5000 条；响应头
   `X-Export-Count`、`X-Export-Truncated` 明示。
3. **列**：`audit_id,user_id,session_id,action,created_at`。只导审计元数据，
   不含会话正文/运行内容。
4. **格式**：复用 `app/core/csv.py`，UTF-8 BOM + CRLF、时间 ISO 8601、公式注入
   前置单引号；`Content-Disposition` 文件名带 UTC 时间，`Cache-Control: no-store`。
5. **失败口径**：`SQLAlchemyError` 返回 503，不返回部分 CSV；非管理员 403。
6. **不做**：无迁移、无前端页面、无异步任务、无下载审计、无日期范围参数
   （列表本身也还没有日期范围；后续由 ADR-0086 补上）。

## 后果

- 管理员可以在保留期清理前导出当前过滤条件下的置顶审计快照。
- 导出是同步请求，5000 行是硬上限；超过时只拿到前 5000 条，需要缩小过滤条件。
- 导出与列表是两次独立查询，可能相差一条新审计；不做稳定快照。
- CSV 含 `user_id`/`session_id`，导出文件应按内部审计材料管理。
- 无迁移、无新索引；复用 `idx_session_pin_audits_time`/用户/会话索引。

## 验证

- `tests/test_admin_pins.py` 覆盖：非管理员 403、正常导出（BOM/CRLF、列顺序、
  过滤后计数）、公式注入字符被前置单引号、截断时 `X-Export-Count=2` 且
  `X-Export-Truncated=true`（测试把上限调成 2 条）、503。
- 实跑：默认 514+40、PG 551+3、Redis 554；ruff 200 files / mypy 116 files；
  前端未改 114/24。

## 待定

- 是否支持按 `created_at` 日期范围导出；已由 ADR-0086 补上。
- 是否记录「谁在何时导出了什么过滤条件」的下载审计。
- 前端管理页已由 [ADR-0085](0085-session-pin-audit-console.md) 补上；异步导出 /
  XLSX 仍未做。
