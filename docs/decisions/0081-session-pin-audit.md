# ADR-0081：会话置顶/取消置顶审计

- 状态：已采纳
- 日期：2026-11-16
- 相关：[ADR-0069](0069-session-pin.md)（会话置顶）、
  [ADR-0073](0073-session-pin-limit.md)（置顶上限）、
  [ADR-0074](0074-session-pin-capacity.md)（置顶容量提示）

## 1. 背景

置顶是 per-user 的展示状态，`pinned_sessions` 只保留「当前是否置顶」：取消置顶
会删掉行，无法回答「谁在何时置顶或取消了这个会话」。企业交接/审计需要这条
操作线索，而现有 `runs`、事件、结构化日志都不能按用户/会话稳定查询，也不能
独立于应用日志留存。

## 2. 备选方案

| 方案 | 为什么没选 |
|---|---|
| 只写结构化日志 | 不可按用户/会话查询，日志轮转后丢失，不能作为管理接口数据源 |
| 复用 `pinned_sessions.pinned_at` | 取消置顶行被删除，历史消失；也无法记录取消动作 |
| 在 `run_events` 记审计事件 | 事件属于 run，置顶动作没有 run；保留期与审计语义不同 |
| 只记最后一次置顶状态 | 无法审计取消/反复置顶；不满足「谁何时做了什么」 |
| 链式哈希/防篡改账本 | 私有化部署维护成本高；当前量级与威胁模型不需要 |
| **独立操作审计表，按显式状态变化一行** | 可查询、实现小、与写入同事务；采纳 |

## 3. 决策

1. 新增 `session_pin_audits` 表：`id`（UUID）、`user_id`、`session_id`、
   `action`（`pin`/`unpin`）、`created_at`。只追加，不更新/删除业务字段。
2. `action` 用 CHECK 限制为 `pin`/`unpin`，避免应用层写错字符串后管理端出现
   无法解释的取值。
3. 只有**显式状态变化**才写审计：重复置顶、重复取消不写；隐藏/恢复会话导致的
   置顶清理不写。审计行与 `pinned_sessions` 的插入/删除在**同一事务**内完成，
   不能置顶成功但审计丢失。
4. 新增只读管理接口 `GET /admin/session-pins`，要求 `ONCALL_ADMIN_ROLES`；
   `user_id`/`session_id` 可选、1–64，`action` 只接受 `pin`/`unpin`，`limit`
   1–200 默认 50，按 `created_at DESC, id DESC` 返回。
5. 不做分页、CSV 导出、前端页面与总数；审计量小，先给有界最近记录，后续按
   真实需要再加。
6. 审计表无外键：会话由 `runs.session_id` 投影，run 可能先被保留策略清掉；
   审计不随会话删除。`user_id` 只存字符串，不依赖用户目录。
7. 审计暂随数据库保留，不接入 `RetentionSweeper`；是否设置独立保留期、以及
   是否清理，留作后续 ADR。审计是治理凭据，默认不应比业务数据更早消失。

## 4. 后果

- 管理员可以按用户/会话/动作查最近的置顶变化，不再依赖日志。
- 每次显式置顶/取消多一次插入；置顶是低频人工动作，写放大可接受。
- 隐藏会话导致置顶被清掉不写审计：这是系统副作用，不是用户显式取消；需要看
  「谁移除了会话」时应查会话移除/恢复审计（ADR-0059 系列）。
- 审计不是防篡改账本：拥有数据库写权限的人仍可修改/删除；当前只保证应用层
  原子写入。
- 无分页/导出/前端页面；管理端先看最近 N 条。审计随库保留，长期增长需要后续
  保留策略。
- 旧客户端不受影响：置顶端点响应不变，审计是服务端副作用。

## 5. 验证

- 覆盖：内存/Postgres 契约（两次 pin + 两次 unpin 写 4 条；按用户/会话/动作过滤；
  重复置顶/取消、隐藏清置顶不写审计）；admin 接口 403 / 列表排序 / 过滤 /
  `limit` / 422 / 503。
- 迁移 `0022`：`upgrade head` → `alembic check` → `downgrade 0021` → `upgrade head`
  往返通过。
- 全量计数见提交时的 README 与验证记录。

## 6. 待定

- 防篡改（链式哈希/外部归档）与审计访问日志；
- 是否把「隐藏导致置顶清理」作为系统动作单独记一条审计；
- 按管理员/租户维度做权限细分（当前只有 admin/employee 两档）。
