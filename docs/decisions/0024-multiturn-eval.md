# 0024 · 多轮评测：追问轮的「指代解对」口径与连续追问的上下文链

- 状态：已采纳（W6 后补）
- 日期：2026-11-10
- 相关：[docs/04-agent-design.md](../04-agent-design.md)、[docs/05-rag-design.md](../05-rag-design.md)、[docs/08-eval-metrics.md](../08-eval-metrics.md)、[ADR-0020](0020-multi-turn-context.md)、[ADR-0022](0022-run-content-visibility.md)、[ADR-0023](0023-run-content-retention.md)

## 背景

多轮上下文（[ADR-0020](0020-multi-turn-context.md)）一直是**有实现、没度量**：

- `docs/08` §3.2 写着「多轮不在评测集里」，[ADR-0020](0020-multi-turn-context.md) 的「待定」
  也记着「要不要把多轮用例加进评测集（需要先定义"指代解对"的判定口径）」；
- 50 条 RAG 用例与 50 条意图分类用例都是**单轮**，`POST /chat/stream` 每轮独立；
- 覆盖多轮的只有 `tests/test_history.py` 的纯函数用例，和一条端到端用例
  （同会话「那怎么办？」引用到 VPN，换会话拒答）。

后果是：改 `needs_context()`、`contextual_query()`、检索参数或提示词时，**多轮没有回归信号**；
「多轮有效」只能说出一条用例，回答不了"多有效、哪里不好"。

真正的难点是**口径**，不是用例数量。追问句（「那怎么办」「那它怎么切」）单独拿去检索
本来就没有可匹配的实词：它命中了文档，既可能是"用上了上下文"，也可能是"碰巧"
——例如「那要等多久」单独就能命中《软件安装与权限申请流程》（标题是「权限申请要多久」）。
把这种句子当成"多轮通过"，得到的通过率不可解释。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 把多轮用例塞进 50 条主集 | 主集的指标（`recall@5` / `cite_acc` / `p95`）是单轮口径，混入多轮会让基线数字不可比；主集评测直接调检索器，没有会话与历史的概念 |
| 用 LLM 当裁判 | 与被测对象同源、不可复现；mock 模式没有模型，违反「能规则判的不用 LLM 判」 |
| 只判「引用是否非空 / 是否拒答」 | 判不出"指代解对"：引用错文档也算非空，拒答和解对也分不开 |
| 把多轮并进主集、另算指标 | 主评测要为此支持会话、setup 断言与"无历史对照"，改动面比独立模块大；分类评测已经验证了「独立评测 + 独立基线」更好讲 |
| 独立入口 + 引用命中标注文档 + **空会话隔离对照** | 规则可判、确定性可复现；隔离对照让"多轮有效"**可证伪**——单独提问也命中就不算数 |

## 决策

### 1. 独立评测：`make eval-multiturn`

`app/eval/multiturn.py` + `app/eval/multiturn_cases.yaml`，与 `make eval`、`make eval-classify`
并列；主集 50 条与分类 50 条的单轮口径不动。

**用例结构**：每条至少两轮；**只判定最后一轮**，前面的轮次是 setup（把上下文铺出来）。
setup 失败 → 整条用例失败，因为追问轮的上下文已经不是用例想测的那一段。

**主指标 `coref_acc`（指代解对率）**：最后一轮的引用命中用例标注的 `must_cite_docs`
（文档级，不看段落），且 setup 全部通过。分母是"正例用例数"，诊断项不在内。

**隔离对照**：同一句追问在**空会话**里单独跑一次，不得命中同一篇文档。
否则这条用例根本没测到指代（是假通过），直接判失败并在报告里写「隔离对照不成立」；
对照 run 本身**没跑完**（空回答）同样判失败——"没命中"必须来自一次正常回答，而不是一次故障。

**答案断言**只在「上下文选对了才能给出这个结论」时使用（例如附件超限 → 企业网盘）；
抽取式选句挑错句是 `answer_acc` 的事（docs/08 §2.1），不在这里冒充指代指标。

**门槛**：`coref_acc ≥ 85%` 才返回 0，供 CI / 本地发现多轮变差；与分类评测同样的用法。

### 2. 诊断项与门槛分离，且诊断项只能判「该拒答」

「那 + 新话题」被上一轮话题稀释是 [ADR-0020](0020-multi-turn-context.md) 已记录的边界
（「那报销怎么走」）。这条用例标 `diagnostic: true`：**只观测、不计入 `coref_acc` 与门槛**，
报告里照常展示通过/失败。

为了防止"把失败用例标成诊断来绕开门槛"，loader 强制：诊断项最后一轮只能是 `must_refuse`。
也就是说诊断项只允许回答一类问题——「不该答的有没有答」——不许拿它承载任意期望。

### 3. 连续追问的上下文链（评测发现的缺陷，本次一并修）

三轮回合用例暴露了一个真实缺陷：`contextual_query` 只拼**紧邻的上一句问题**。
「VPN 下载」→「那接下来要做什么」→「那还要注意什么」时，第三句的检索词变成
「那接下来要做什么 那还要注意什么」，VPN 不见了，召回直接为空（隔离对照的日志里能
看到 `context_query`）。

修复（`app/agent/history.py`）：新增 `_context_anchor`，按时间顺序累积最近 `MAX_TURNS` 轮
**用户问题**，总长仍受 `CONTEXT_QUERY_CHARS`（80 字）约束；预算不够时丢更早的轮次、
保证最近一句完整（它决定指代指向），只有单句自身超预算才截断。

三个"不变"是有意的：单轮（非追问）原样返回；两轮只有一句问题可拼，检索词与旧实现完全一样；
主集 50 条没有历史，`context_query == query`，指标零变化。

### 4. 用例设计约束（loader 强制，不是靠自觉）

- 第 2 轮起必须能被追问启发式判定（`needs_context() == True`），否则 **SystemExit**：
  启发式不认它是追问，就不会拼检索词，测到的是单轮检索。
- **所有前序轮次（setup）必须标 `must_cite_docs`**：它们不判引用的话，跑挂了只会让追问轮
  "莫名其妙"答不出来，setup_failures 也就永远是空的。
- **正例必须标 `must_cite_docs`**（`coref_acc` 的分母是"引用命中"）；拒答类只能进诊断项
  （`diagnostic: true` + `must_refuse`）；同一轮不允许既要求命中文档又要求拒答。
  这样 `coref_acc` 不会被"答对了没答"的用例稀释，诊断项也不能承载任意期望。
- 至少一条正例、id 唯一、至少两轮；只剩诊断项时直接 **SystemExit**（否则 `coref_acc`
  是个空指标，报告会把它当成 0% 或 100%，两种都是假的）。
- 追问句要避开文档里的实词（例如不用「那过期了怎么办」——「过期」单独也能命中密码文档），
  否则隔离对照不成立。这条是写用例时踩出来的，记在这里。

## 后果

- **多轮质量有了回归信号**：改 `history.py`、检索参数或提示词时跑 `make eval-multiturn`；
  主集回归超过 -3pp 不合并的规则同样适用于 `coref_acc`。
- 结果属**样本内**：9 条正例参与过追问启发式设计；只覆盖"被启发式判定为追问"的句子，
  启发式漏判的短句不在这里。
- `coref_acc` 是**文档级**：引用对了文档就算解对，段落级指代（"同一段"）不判。
- `coref_acc` 只判**命中**，不判精度：追问轮多引一篇无关文档不扣分（多余引用由主集的
  `cite_acc` 约束）。例如 `mt-vpn-err502` 的追问轮同时引用了打印机文档，本集仍然算解对。
- 评测成本：每条正例多一次隔离 run（10 条用例共 30 次 run；诊断项没有"必须命中的文档"，
  不跑对照），进程内约 1.7 秒，`uv run` 冷启动另算，可接受。
- 诊断项目前 **0/1**：`那报销怎么走` 在合并检索词后被保修文档带偏，而语料里其实有
  《差旅报销流程》。这是已知边界，**本次不修**——修法（原句 + 合并句双检索 RRF、原句优先、
  名词短语判定）会影响主集召回与延迟，需要单独 ADR 与回归。
- `context_query` 变长（最多 80 字 + 本轮）：检索的 tokens 计算量略增，未做延迟基准；
  主集 p95 与基线一致（83ms）。检索和 `finalize` 选句都吃这个查询，3 轮以上时旧话题
  可能把选句带偏；多轮集只判引用命中，没有判选句质量（归 `answer_acc`）。
- [ADR-0020](0020-multi-turn-context.md) 的表述「把上一轮问题拼进 `context_query`」被本次修正：
  现在拼的是**最近几轮问题**（连续追问才生效），单轮/两轮行为不变。

## 验证

- `tests/test_multiturn_eval.py`（18 条）：用例可加载且每条追问都被启发式识别；
  loader 拒绝"启发式不认的追问"、拒绝"诊断项不是拒答"、拒绝"拒答用例不标诊断"、
  拒绝"同一轮既命中又拒答"、拒绝"只有诊断项的文件"、拒绝"setup 不判引用"、拒绝单轮用例；
  隔离 run 空回答（没跑完）被判"隔离对照未完成"而不是通过；
  引用按标题/小节命中；拒答带引用被判失败；隔离对照能抓到假通过；
  `run_case` 真的带历史且隔离跑不含历史；同一句追问"带历史命中 / 空会话不命中"；
  只有正例计入 `coref_acc`；基线 `coref_acc == 1.0`、隔离 9/9；`main()` 写出 md + json。
- `tests/test_history.py` 新增 3 条：连续追问保留最初话题锚点、不拼助手回答、
  预算不足时保留最近一句。
- 基线：**`coref_acc 100%（9/9）`、隔离对照 9/9、诊断 0/1**，
  见 [docs/eval/multiturn-v1.md](../eval/multiturn-v1.md)。
- 主集回归：**50/50**、`cite_acc 97.09%`、`recall@5 100%`、`p95 83ms`，与
  [baseline-v1](../eval/baseline-v1.md) 一致（上下文链对单轮零影响）。
- 完整回归：默认 **351 passed + 24 skipped**；带 Postgres **375 passed**；
  `ruff check` / `ruff format --check`（153 files）/ `mypy app`（96 files）通过。
- 迁移无变化（`alembic check` 无漂移）；前端未改动。

## 待定

- 「那 + 新话题」的稀释：双检索 RRF（原句 + 合并句）还是原句优先，需要主集召回与延迟回归
- 追问判定要不要模型兜底（多一次调用换更准的指代解析，mock 模式量化不了）
- 真实 provider 下的多轮收益（当前只有规则路径）
- 段落级指代（引用同一段）是否值得判；文档级已经能证伪"没用上下文"
- 用例集扩充：9 条正例仍小；setup 轮次也只判引用，不判可执行性
- 会话历史 TTL 与跨会话长期记忆（跟随 ADR-0023 的正文保留期，见 ADR-0020 待定）
