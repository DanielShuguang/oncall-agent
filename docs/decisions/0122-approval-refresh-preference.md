# ADR-0122：审批统计自动刷新开关持久化

## 背景

ADR-0116 增加了「自动刷新：开/关」，但开关只存在组件状态里：一次刷新、切页或重新登录就回到默认开启。管理员为了排查问题暂停轮询，通常需要跨刷新保持这个选择；否则暂停没有实际意义。

## 备选方案

| 方案 | 取舍 |
|---|---|
| 只用 `sessionStorage` | 同标签页可用，但新标签页/重开浏览器丢；不足以表达「这个浏览器的管理员不想自动刷新」 |
| 服务端按用户保存 | 跨设备一致，但要新表/接口/清理策略，且这是纯界面偏好，不值得引入服务端状态 |
| `localStorage` 按浏览器保存 | 刷新/重开仍生效；实现小；换账号时清理即可 |
| 不持久化（ADR-0116 现状） | 实现最小，但暂停每次刷新都失效 |

## 决策

1. 新增 localStorage key `oncall.approval-stats-auto-refresh.v1`，值只写 `on` / `off`。
2. 读取时默认 `true`；只有明确 `off` 才关闭，缺失、损坏或存储不可用都按默认开启处理。
3. `useApprovalStats` 首次渲染从 storage 初始化 `autoRefreshEnabled`；`setAutoRefresh` 同步写 storage。
4. 切换登录账号时由 `clearLocalPreferences` 删除该 key，避免把上一位用户的界面偏好带给下一位。
5. 自动刷新失败、暂停、重新开启立即补拉的语义保持 ADR-0115/0116 不变。
6. 纯前端，无后端接口、无迁移；不做跨设备同步，也不改变 30 秒间隔。

## 后果

- 同一浏览器、同一账号刷新后保持暂停/开启；换浏览器或隐私模式仍可能回到默认。
- 偏好是账号切换清理的本地状态，不是服务端用户设置；多副本部署无影响。
- 存储失败时只影响持久化，不阻断页面；当次状态仍可用。

## 验证

- `approvalStatsRefresh.test.ts` 增加默认开启、写 `off` 后读回关闭、损坏值回到开启、清除后回到默认、存储不可用不抛错。
- `localPreferences.test.ts` 增加该 key 在切换账号时被删除。
- 前端 **33 files / 172 tests**、`tsc --noEmit`、`oxlint` 0/0（148 files）、`oxfmt --check` 156 files、`pnpm build` 2950 modules 通过。
- 后端未改，沿用默认 538+42 / PG-only 577+3 / PG+Redis 580。
