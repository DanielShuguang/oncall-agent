# ADR-0124：审批统计自定义刷新间隔

## 背景

ADR-0123 让审批统计的刷新间隔变成 15/30/60 秒三档浏览器偏好，默认 30 秒。这个范围覆盖了大部分值班场景，但现场节奏不一定正好落在三档上：交接班前有人希望 10 秒，低峰巡检有人希望 120 秒。只能从三档里选，会逼用户改代码或接受不合适的频率。

## 备选方案

| 方案 | 取舍 |
|---|---|
| 保持三档 | 实现最简单，但“差一点”的需求永远无法满足 |
| 允许任意秒数 | 需要输入校验；频率过低会让浏览器定时器不可靠，频率过高会放大服务端压力 |
| 只允许 5–300 的整数 | 覆盖实际场景，同时给定时器和服务端一个明确边界；输入框仍可回车/失焦应用 |
| 做成账号偏好 | 需要新表/接口与跨设备同步，和当前“本地界面偏好”边界不符 |

## 决策

1. 自定义范围固定为 **5–300 秒的整数**（含两端）；默认仍 30 秒。
2. 15/30/60 继续作为快捷档；下拉框增加「自定义…」，旁边是数字输入框。
3. 自定义值写同一个 key `oncall.approval-stats-refresh-interval.v1`；读取时接受 5–300 的整数，其他值（含小数、`4`、`301`、损坏 JSON）回退 30。
4. 修改间隔只重启本地定时器，**不立即发请求**；自动刷新仍只在页面可见时轮询。
5. 输入框在回车或失焦时应用；非法值恢复为当前生效值，不写入存储。
6. 只影响本浏览器，不跨设备同步；切换账号仍由 `clearLocalPreferences` 清理。
7. 不新增后端接口、定时任务或迁移。

## 后果

- 用户可以在 5–300 秒之间按现场节奏设置，快捷档仍然可用。
- 输入框每次修改不会立即写存储；只有合法值才会调用 `setRefreshInterval`。
- 极小间隔（5 秒）会增加浏览器请求频率，但页内只有一处统计请求且仅在可见时轮询，属可接受范围。
- 仍不解决服务端主动推送或低峰自动降频；那是另一种架构。

## 验证

- `approvalStatsRefresh.test.ts`：默认 30；`45`/`5`/`300` 可读；`4`/`301`/损坏值回退 30；清除回 30。
- 前端类型检查、`oxlint`、`oxfmt --check`、`pnpm test`、`pnpm build` 通过；后端未改。
- 不做服务端接口、跨设备同步、账号级偏好或迁移。

## 待定

- 是否允许按用户设置不同默认值（需要账号偏好表）。
- 是否在低峰自动降频（需要服务端时间/负载信号）。
- 是否在 5 秒档位加二次确认，避免值班页长时间高频轮询。
