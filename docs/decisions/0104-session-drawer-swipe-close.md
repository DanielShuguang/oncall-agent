# ADR-0104：窄屏会话抽屉左滑关闭

## 背景

ADR-0076 把窄屏（<640px）会话栏改成复用的 `SessionList` 抽屉，关闭方式有遮罩、Escape、
右上角 X、选择会话或新会话；ADR-0077 补了焦点陷阱与背景滚动锁定。README 与 ADR-0076 的
「待定」仍写着没有滑动关闭。

移动端用户单手操作时，右上角 X 距离拇指较远；左滑是抽屉的常见关闭手势，且不需要引入手势库。

## 备选方案

| 方案 | 取舍 |
|---|---|
| 不实现 | 否决：README 明写「仍没有滑动关闭」，移动端关闭路径不完整 |
| 引入手势库 | 否决：为一个水平滑动增加依赖，和 ADR-0008 的最小依赖原则冲突 |
| 实时跟手 + 回弹动画 | 否决：需要持续改 transform/读布局，容易与焦点陷阱、背景滚动锁定互相干扰；本次先做最小可用 |
| 松手后按总位移判定（采纳） | 只在 `touchend` 计算一次 `dx`/`dy`，不改 DOM、不新增依赖 |

## 决策

1. 新建纯函数 `web/src/features/chat/drawerSwipe.ts`：
   - 关闭阈值 `DRAWER_SWIPE_CLOSE_PX = 80`；
   - 水平占优系数 `HORIZONTAL_DOMINANCE = 1.5`；
   - `isDrawerSwipeClose(dx, dy)` 等价于 `dx <= -80 && abs(dx) >= abs(dy) * 1.5`。
2. `SessionList` 在 `aside` 上挂 `onTouchStart` / `onTouchEnd` / `onTouchCancel`：
   - 只在 `mobileOpen` 且单指触摸时记录起点；
   - `touchend` 用 `changedTouches[0]` 减起点，满足阈值就调用 `onCloseMobile()`；
   - `touchcancel` 清空起点，不关闭。
3. 不做实时跟手位移、不做动画、不改变抽屉宽度；也不支持右滑打开（抽屉由菜单按钮打开）。
4. 手势只作用于抽屉容器，不阻止内部按钮/输入框的点击；垂直滚动仍由列表自身处理。
5. 不新增持久化、后端接口或迁移。

## 后果

- 窄屏抽屉支持「从左向右滑入、向左滑出」的常见手势；达到 80px 且水平位移至少为垂直的
  1.5 倍才关闭，避免列表滚动误触。
- 没有拖动反馈，用户需要滑够阈值再松手；如果后续要做跟手动画，需要重新评估与焦点陷阱/
  背景滚动锁定的交互。
- 纯函数覆盖阈值、不足、反方向/垂直、斜向不占优四类边界，组件层不引入手势库。

## 验证

- `drawerSwipe.test.ts`：4 个用例通过（80px 边界、79px 不足、向右/垂直、斜向不占优）。
- 前端全量：`vitest` 28 files / 144 tests、`oxlint` 0/0（135 files）、`oxfmt --check`
  143 files、`tsc --noEmit`、`pnpm build` 2941 modules 通过。
- 后端未改：默认 533+42 / PG 572+3 / PG+Redis 575。

## 待定

- 是否需要拖动过程中的位移反馈与回弹动画；
- 是否需要可配置的关闭阈值（当前固定 80px）；
- 是否支持从屏幕左缘右滑打开抽屉（当前只由菜单按钮打开）。
