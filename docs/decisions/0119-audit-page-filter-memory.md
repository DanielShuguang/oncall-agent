# ADR-0119 置顶/导出审计页记住非日期过滤

## 背景

ADR-0118 给置顶审计页和导出审计页各加了一个日期预设 key，刷新后能恢复上次的 UTC 日期窗口。但两页的用户、会话、动作（置顶/取消）以及导出页的资源过滤仍然只在当前内存里，刷新即丢；管理员按某个账号核对一串操作时，每次都要重新输入。

恢复审计页的 ADR-0078 已经记住了用户/会话过滤与统计窗口，但那是恢复审计页专属的 key。直接复用会让两页互相覆盖，也把「日期预设」和「对象过滤」混成一份状态。

## 备选方案

| 方案 | 结论 |
|---|---|
| 复用恢复审计页的 `oncall.audit-filters.v1` | 不采纳：跨页互相覆盖，且恢复审计的 `statsDays` 与置顶/导出无关 |
| 把日期和对象过滤放进同一个 key | 不采纳：日期有独立预设语义（ADR-0118），混在一起后手填日期会把对象过滤一起写脏 |
| 每页独立 key，只存非日期过滤 | 采纳：日期仍由 ADR-0118 负责，对象过滤单独记忆，互不干扰 |
| 不记忆，刷新清空 | 不采纳：管理员核对同一对象时重复输入成本高 |

## 决策

1. 新增两个独立 key：`oncall.pin-audit-filters.v1`、`oncall.export-audit-filters.v1`。
2. 置顶审计只存 `userId`、`sessionId`、`action`（`all|pin|unpin`）；导出审计只存 `userId`、`resource`（空字符串表示全部资源）。**不存日期**。
3. 读取时 trim 字符串，id 长度限制 1–64；非法 `action`/`resource` 按默认值忽略，不把脏值带入请求；损坏 JSON 或存储不可用静默回退到空过滤。
4. 页面初始化时把「过滤记忆」与「日期预设」合并成初始 `filters` 与草稿；不会先发一次空请求再切换过滤。
5. 点「筛选」或「应用」时写入/更新本页过滤 key；清除筛选时同时删除本页过滤 key 和日期预设 key；只改日期不改对象过滤时，对象过滤保持不变。
6. 切换账号时由 `clearLocalPreferences` 删除两个新 key，避免上一位用户的过滤留在下一位用户界面上。

## 后果

- 刷新置顶/导出审计页会恢复上次的对象过滤与日期预设，但日期仍只按预设保存；手填的非预设日期不会跨刷新保留。
- 三个审计页互不覆盖：恢复审计、置顶审计、导出审计各用自己的 key。
- 过滤记忆只存在浏览器本地，不跨设备、不跨账号；服务端仍然按请求参数做权限与 365 天校验，本地记忆不绕过任何校验。
- 不做：跨页共享过滤、记住手填日期、同步到服务端、过滤方案命名/收藏。
