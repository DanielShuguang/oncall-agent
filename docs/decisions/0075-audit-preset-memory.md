# ADR-0075：审计页记住上次日期预设

## 背景

ADR-0071 给审计页增加了五个 UTC 日期快捷预设（近 7/30/90 天、本月、上月），但页面刷新或下次打开时不会保留选择；交接、值班复盘往往反复使用同一窗口。README 的已知局限明确写了「不记住上次选择」。

这次只解决「预设」的记忆，不扩大到用户/会话过滤或统计窗口；后两项由后续
[ADR-0078](0078-audit-filter-memory.md) 补上。

## 备选方案

| 方案 | 结论 |
|---|---|
| 不记住（现状） | 每次重新点，体验差 |
| 记住完整起止日期 | 下次可能落到已经过期的固定窗口，且无法区分用户是否想继续用旧日期 |
| 记住预设 ID（采纳） | 相对当前 UTC 日期重新计算，语义稳定；只存一个短字符串 |
| 存到服务端用户偏好 | 跨设备，但需要新表/接口与身份同步，超出本次范围 |
| 用 URL query 记住 | 可分享/可回退，但会把筛选写进地址栏，审计页当前没有路由参数设计 |

## 决策

1. 仅记住**预设 ID**（`last7/last30/last90/thisMonth/lastMonth`），存放在浏览器 `localStorage`，键 `oncall.audit-date-preset.v1`。
2. 打开审计页时读取预设并**自动应用**到列表、统计与导出；快捷按钮显示为激活态，用户可点「清除」恢复全部数据。
3. 手工把日期改成非预设范围并点「筛选」时清除已保存的预设，避免下次落到过期的手填窗口；只修改用户/会话过滤、日期仍是当前预设范围时保留记忆。
4. 预设无效、存储不可用或读取抛错时按「没有预设」处理，不阻塞页面；写/删失败静默降级。
5. 不改后端、不加迁移；预设只影响前端审计页，统计接口的 `days` 仍由日期范围二选一规则决定。
6. 本 ADR 不记住用户/会话过滤、不记住统计窗口、不做跨设备同步；前两项由
   [ADR-0078](0078-audit-filter-memory.md) 补上。

## 后果

- 同一浏览器下次打开审计页会落在上次的预设窗口，可能暂时看不到窗口外数据；清除即可恢复。
- 共享电脑会继承上一位使用的预设；预设本身不含敏感数据。
- 预设按当前 UTC 日期重新计算：例如「上月」在新月份打开时指新的上月，而不是旧固定日期。
- 存储不可用时退化为「不记住」，不影响筛选、统计、导出。
