# ADR-0118：置顶/导出审计页记住日期预设

## 背景

恢复审计页从 ADR-0075 起把快捷日期预设 ID 存到浏览器
`oncall.audit-date-preset.v1`，刷新后自动应用。ADR-0091 和 ADR-0107 给置顶审计、
导出审计页加了同样的五个 UTC 预设，但明确「点击即应用、刷新不记忆」；管理员排查
跨天事件时每次刷新都要重新点。

## 备选方案

| 方案 | 结论 |
|---|---|
| 不记住 | 保持现状，刷新回空筛选；排查体验差 |
| 三页共用一个 key | 一个页面选的预设会覆盖另外两页，跨页耦合 |
| 每页独立 key | 采纳；互不影响，账号切换统一清理 |
| 记住手填日期 | 可能保存过期窗口；不采纳，只存预设 ID |

## 决策

1. 新增两个 key：`oncall.pin-audit-date-preset.v1`、
   `oncall.export-audit-date-preset.v1`；恢复审计页仍用 ADR-0075 的
   `oncall.audit-date-preset.v1`，三者互不读写。
2. 只持久化预设 ID，不保存手填的具体日期；手填任意非预设窗口或清除筛选会删除该页 key。
   手填区间如果恰好等于某个预设，会按该预设 ID 保存（与点击预设等价）。
3. 页面初始化时读取 key 并校验枚举；有效预设直接生成日期窗口作为初始筛选，
   避免「先空请求一次再切到预设」的闪烁。无效值/存储不可用按无记忆处理。
4. 点击预设或「筛选」时，如果草稿区间精确匹配一个预设，写入该页 key；否则删除。
   只改用户/会话/动作过滤而日期仍是预设时保留。
5. 清除筛选同时删除该页 key。
6. 切换账号时，`clearLocalPreferences` 一并清理两个新 key，避免下一位管理员继承。
7. 纯前端；不改接口、不加迁移。

## 后果

- 刷新置顶/导出审计页会回到上次的 UTC 日期预设；只改用户/会话/动作过滤也会保留。
- 手填的非预设日期不保存；精确等于预设的区间会按预设保存；刷新后不会落回一个可能已经过期的自定义窗口。
- 三个页面各自记忆，互不覆盖；共享浏览器换账号时由 ADR-0080 的清理链路删除。
- 不跨设备、不做服务端同步。

## 验证

- 前端 `pnpm test`：32 files / 163 tests；`tsc --noEmit`、`oxlint` 0/0（145 files）、
  `oxfmt --check` 153 files、`pnpm build` 2947 modules。
- `auditDatePresets.test.ts` 新增独立 key 用例；`localPreferences.test.ts` 断言切换账号时
  三个审计预设 key 一并清理；后端未改，默认 537+42 / PG 576+3 / PG+Redis 579。
