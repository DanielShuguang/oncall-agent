# ADR-0105：工具历史游标 TTL 可配置

## 背景

ADR-0102 给工具配置变更历史的 keyset 游标加了固定 1 小时有效期：过期返回
`CURSOR_EXPIRED`，前端用「重新加载」回到第一页（ADR-0103）。当时把「TTL 是否可配置」
列为待定；固定 1 小时对多数管理页足够，但现场审计节奏差异很大：慢网络/长会议可能超过
1 小时，严格环境又希望缩短窗口。写死在代码里只能改版本，不能按部署调整。

游标不提高权限，也不是下载凭证；TTL 只决定「旧分页位置还能用多久」。因此这里只把
1 小时改成配置项，默认不变，不做签名、不延长到无限。

## 备选方案

| 方案 | 取舍 |
|---|---|
| 固定 1 小时 | 行为可预测；现场无法按审计节奏调整 |
| 不设过期 | 旧游标在数据保留期内一直可用，视图可能长期停在过去 |
| 环境变量分钟数（采纳） | 默认 60 分钟，启动期校验范围；部署可按需调整，不改契约 |

## 决策

1. 新增 `ONCALL_TOOL_HISTORY_CURSOR_TTL_MINUTES`，默认 `60`，范围 `[1, 1440]`；
   启动期校验，非法值直接拒绝启动。
2. `Settings.tool_history_cursor_ttl_s` 统一换算为秒；游标编码仍写绝对过期时间 `e`，
   解码只比较 `e` 与当前时间，因此改配置只影响新签发的游标。
3. 编码函数保留 `ttl_s` 参数（默认常量 1 小时），路由显式传
   `get_settings().tool_history_cursor_ttl_s`；测试可直接注入 TTL，不依赖环境。
4. 默认值不改变既有行为；升级后旧游标仍按自己的 `e` 判定，不会因为改配置被追溯延长。
5. 只影响工具历史分页游标；历史查询窗口、导出、其他资源的游标不受影响。
6. 无表、无索引、无迁移。

## 后果

- 默认部署仍是 1 小时；需要更短/更长窗口时改环境变量并重启即可。
- 配置上限 1440 分钟（24 小时），避免把分页位置变成长期有效的「半持久视图」。
- 修改 TTL 不会使已经签发的游标立刻失效或续期；旧游标保留原过期时间。
- 多副本各自读取同一配置；若滚动发布期间副本配置不同，TTL 以签发副本为准，属可接受的
  短期差异。

## 验证

- `server/tests/test_config.py`：拒绝 0 与 1441，接受 15 并换算为 900 秒，默认 60。
- `server/tests/test_tool_history.py`：直接调用编码/解码，`ttl_s=120` 时第 120 秒仍有效、
  第 121 秒返回 `CURSOR_EXPIRED`；分页用例通过 monkeypatch `get_settings()` 返回 TTL=120，
  断言路由签发的 `e` 距当前不超过 120 秒，覆盖「路由真的读取配置」这一接线。
- 默认 534+42、PG 573+3、PG+Redis 576；ruff 208 / format 208 / mypy 119；前端无改动
  28 files / 144 tests。
- 详见 [ADR-0102](0102-tool-history-cursor-expiry.md)、[ADR-0103](0103-tool-history-cursor-reload.md)。
