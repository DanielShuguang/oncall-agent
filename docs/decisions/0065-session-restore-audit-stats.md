# ADR-0065：会话恢复审计统计

- 状态：已采纳
- 日期：2026-11-14
- 相关：[ADR-0059](0059-session-restore-audit.md)（审计表）、
  [ADR-0060](0060-session-restore-audit-pagination.md)（分页）、
  [ADR-0063](0063-session-restore-audit-console.md)（管理页）、
  [ADR-0064](0064-session-restore-audit-total.md)（列表总数）

## 1. 背景

审计管理页能按用户/会话过滤、翻页、看首屏总数与导出 CSV，但回答不了
「最近 30 天一共恢复了多少次/涉及多少用户/多少会话」。列表总数只在某个过滤
条件下有意义；要得到全局规模，管理员只能把过滤清空后逐页加载或导出后自己算。
恢复审计保留 365 天，交接、容量评估和异常排查需要一个窗口内的聚合视图。

审批统计（ADR-0048/0050/0051/0058）已经证明「窗口汇总 + 稀疏日趋势」在管理页
足够用；审计数据量远小于审批，不需要预聚合或缓存表。

## 2. 备选方案

| 方案 | 取舍 |
|---|---|
| 复用列表 `total`，让管理员自己加过滤 | 只能回答单个过滤条件；无法给用户数/会话数/日趋势；否决 |
| 只返回当前窗口的汇总，不给日趋势 | 能回答规模，但看不到「哪几天集中」；管理页价值有限；否决 |
| 由前端遍历所有分页再聚合 | 最多 365 天、无上限；多请求、慢、容易漏；否决 |
| 物化表/定时任务预聚合 | 当前审计量小，新增表和维护成本不划算；否决 |
| 单独加统计接口，窗口 + 汇总 + 稀疏日趋势 | 一次请求、无迁移、复用现有时间索引；采纳 |

## 3. 决策

1. 新增 `GET /admin/session-restores/stats?days=30`，管理员只读接口。`days`
   取值 1–365，默认 30；越界 422。
2. 窗口为 `[until - days, until]`，`until = datetime.now(UTC)`；两端都包含。
   `since`/`until` 原样返回，客户端不需要自己猜窗口边界。
3. 汇总口径：
   - `restores`：窗口内审计行数，即恢复操作次数；
   - `sessions`：窗口内 `restored_count` 之和，即真正恢复的会话数；
   - `users`：窗口内去重后的 `user_id` 数；
   - 不统计请求了但未恢复的 id，也不读会话正文。
4. `daily` 按 `restored_at` 的 **UTC 自然日**聚合，只返回有恢复活动的日期，
   按日期升序，不补零。每项 `{day, restores, sessions}`；`restores` 是操作数，
   `sessions` 是当天真正恢复的会话数之和。日汇总之和与总汇总一致。
5. 统计是全局的：不接收 `user_id`/`session_id` 过滤，也不受管理页当前过滤影响。
   页面卡片明确标注「全部用户」；按用户/会话看明细仍用列表。
6. 无迁移、无新索引；窗口过滤复用 `idx_session_restore_audits_time`。实现用
   一条汇总查询（`count(*)`、`count(distinct user_id)`、`sum(restored_count)`）
   加一条按 UTC 日期分组的查询；两条查询不是同一快照，接受轻微不一致。
7. 前端在审计页顶部加「近 7/30/90 天」切换与三个汇总数字，不做图表库、
   不做按天明细表。统计失败只显示错误卡，不影响列表/导出；旧后端没有该接口时
   同样降级为错误卡。
8. 不改变列表、导出、保留期与权限；不新增下载/审计日志。统计只读审计元数据，
   不引入会话内容或用户目录。

## 4. 后果

- 每次打开/切换统计窗口多两条聚合查询；365 天窗口会比 7 天慢，但数据量小且
  有时间索引，暂不做缓存/近似值。
- 管理员能看到全局恢复节奏，但不能直接按统计下钻到某天/某用户；需要配合列表
  过滤或 CSV。
- `restores` 与 `sessions` 语义不同：一次批量恢复多个会话只算一次操作、多个会话；
  页面标签必须区分，避免把「恢复操作数」误读成「恢复会话数」。
- 统计窗口与列表过滤互不影响；管理员清空过滤后看到的 `total` 才与统计口径接近，
  但仍可能因并发/保留清理不同步。
- 旧前端忽略新接口；新前端遇到旧后端 404 时只显示统计错误，不影响主列表。

## 5. 验证

- 默认 **499 passed + 40 skipped**；真实 Postgres **536 passed + 3 skipped**；
  Postgres + Redis **539 passed**。
- `ruff check` / `ruff format --check`（194 files）/ `mypy app`（113 files）通过。
- 前端 `tsc`、**85 tests / 17 files**、`oxlint` 0/0（72 files）、
  `oxfmt --check` 80 files、`pnpm build` 通过。
- 覆盖：store 契约的窗口汇总/空窗口（内存与 PG）；API 的 403、`days` 1–365
  越界 422、汇总与 `daily` 之和一致、统计失败 503；前端统计请求参数。
- 无迁移；审计写入/分页/导出/保留路径未改。

## 6. 待定

- 统计按用户/会话过滤或下钻；
- 日趋势图/按小时分布（与审批统计不同，审计量更小）；
- 统计结果缓存或物化（当前每次实时聚合）；
- 统计 CSV 导出、下载审计；
- 可配置时区（当前固定 UTC，与审批统计一致）。
