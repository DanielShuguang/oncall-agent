# ADR-0044：运行过程载荷上限

- 状态：已采纳（W6 后补）
- 日期：2026-11-13
- 相关：[ADR-0035](0035-run-timeline-replay.md)（运行过程回放）、[ADR-0036](0036-session-detail-batch.md)（批量会话详情）、[ADR-0021](0021-data-retention.md)（事件保留）

## 1. 背景

运行过程（ADR-0035）在读取 `runs/{id}` 时，把事件里的 `tool.call.args` 与
`tool.result.result` 原样投影成时间线。事件本身不设大小上限：内置工具的返回很小，
但治理层是为 MCP / HTTP 工具准备的，一个查询日志或返回大 JSON 的外部工具就可能带回来
几百 KB 到数 MB。批量会话详情（ADR-0036）又会一次拼一页 run，单条载荷会被放大 N 倍。

当前没有截断，也没有分页：

- 详情响应会随工具结果线性变大，浏览器 `JSON.stringify` 在渲染线程同步执行；
- 运维/审计真正需要的是「调过什么、结果大概是什么」，不是把整段结果塞回浏览器；
- 事件一旦写入就是只增不改的证据（R1），不能在写入侧静默截断。

ADR-0035 的「待定」里已经写了「单条工具结果/参数的字节上限与折叠预览」，这个 ADR 把它兑现。

## 2. 备选方案

| 方案 | 结论 |
|---|---|
| 写入事件时截断 | 否：破坏证据完整性，且旧事件无法回溯 |
| 前端只折叠不裁剪 | 否：服务端仍然传输全量，内存与带宽已经花掉 |
| 超过上限直接丢弃结果 | 否：会看不到「调用已发生、结果被丢弃」，容易误判工具没执行 |
| 读侧按预算裁剪成预览（采纳） | 是：事件不动，响应有界，仍保留「有大载荷」的事实 |
| 按工具配置上限 / 总量预算 | 留到后续；v1 用统一常量，先消除无界响应 |

## 3. 决策

1. **只在读取侧裁剪**：`server/app/runs/timeline.py` 在 `build_timeline` 投影时处理，
   事件表、`runs` 表与保留清理都不变，无迁移。
2. **统一预算**：单个 `args` / `result` 的紧凑 JSON 超过
   `MAX_TIMELINE_PAYLOAD_CHARS = 4096` 字符即裁剪；预览保留前
   `MAX_TIMELINE_PREVIEW_CHARS = 1024` 字符。审批的 `args` 同样处理。
3. **不静默丢弃**：超限字段替换为
   `{"truncated": true, "original_chars": N, "preview": "<前 1KB>"}`，
   所在条目加 `truncated: true`；前端按预览文本渲染并显示原始字符数，不再当 JSON 解析。
4. **按字符而不是 UTF-8 字节计数**：实现简单、跨语言一致；中文按 1 字符计，
   字节数会低估，但预算是防「数量级失控」而不是精确计费，可接受（列入待定）。
5. **不改变时间线的 20 项上限**：条数仍由 `MAX_TIMELINE_ITEMS` 控制；本 ADR 只解决单条载荷。
6. **完整载荷仍在事件里**：保留期内仍可通过事件表/回放核对，但普通详情不返回；
   未来若需要「管理员看完整载荷」，应单独接口 + 权限，不能放宽普通详情。
7. **不做**：按工具配置预算、响应总量预算、服务端压缩、前端展开完整载荷。

## 4. 后果

- 单条工具参数/结果的最大展示体积从「无上限」降到约 1KB 预览 + 元数据；一页最多
  20 项，响应大小有上界，详情与批量详情都不会被单条结果拖垮。
- 超限结果不再能直接从运行过程里读到全文；排障需要查事件（保留期内）或让工具自己收敛输出。
  这是用可读性换响应稳定性，必须在 UI 上明确标注「已截断」，不能让用户以为结果就这么短。
- `original_chars` 是紧凑 JSON 的字符数，和人类阅读的「字数」不完全等价。
- 事件里的原始 payload 仍按 ADR-0021 清理；清理后运行过程整体不可用，与 ADR-0035 一致。
- 写入侧没有变化，历史 run 打开时也会按新规则裁剪，不需要回填。

## 6. 待定

- 按工具配置预算（例如日志类工具允许更大）与一次响应的总预算。
- 按 UTF-8 字节而不是字符计数。
- 管理员/审计角色查看完整载荷的单独接口（需要权限与审计）。
- 前端「展开完整载荷」：必须走新接口，不能把事件表直接暴露给浏览器。
- 超限时的结构化预览（保留字段名、只裁长字符串）而不是整段替换，需前端配合。
