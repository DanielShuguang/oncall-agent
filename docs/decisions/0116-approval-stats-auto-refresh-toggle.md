# ADR-0116：审批统计自动刷新开关与失败提示

## 背景

ADR-0115 让审批统计在页面可见时每 30 秒自动刷新，但只受标签页可见性控制：
管理员无法在看历史快照、截图或排查时暂停请求；自动刷新失败又是静默的，界面只显示
上一份「更新于」时间，值班人员无法区分「没有新数据」与「刷新失败」。

## 备选方案

| 方案 | 取舍 |
|---|---|
| 保持总是自动刷新、失败静默 | 实现最简单，但无法暂停，失败不可见 |
| 服务端推送/告警 | 超出当前页面需求，需要连接与多副本广播 |
| 持久化开关到账号/浏览器 | 需要新偏好键与账号切换清理规则，当前收益不足 |
| 前端临时开关 + 失败提示（采用） | 纯前端、无迁移；刷新节奏仍由用户与页面可见性共同控制 |

## 决策

1. 自动刷新默认开启；开关只在当前页面会话内有效，刷新页面恢复开启，不新增 localStorage。
2. 关闭后清除定时器与 `visibilitychange` 监听，隐藏/切回页面都不再自动请求；已在途的
   请求允许完成，不回滚已发出的请求。
3. 重新打开时立即静默补拉一次，不必等下一个 30 秒；随后恢复「可见时每 30 秒」。
4. 自动刷新失败显示中性提示「自动刷新失败，稍后重试」，保留旧统计与上次更新时间；下一次
   静默成功或手动成功清除提示。手动刷新失败仍清空统计与更新时间，并清除自动刷新提示。
5. 暂停时清除上一轮自动刷新失败提示；暂停前已在途的静默请求即使失败也不再点亮提示（用当前开关状态的 ref 守卫）；重新开启时先清旧错误再补拉。手动刷新按钮不受开关影响。
6. 无新接口、无表/迁移、无权限变化；仍不做 SSE/WebSocket、服务端缓存或告警。

## 后果

- 管理员可以暂停轮询；暂停期间数据不会更新，但仍有手动刷新与更新时间可判断新鲜度。
- 自动刷新失败不再完全静默，但只提示稍后重试，不自动重试、不弹窗、不告警。
- 开关不持久化：换标签页/刷新后回到默认开启；多副本部署无状态影响。
- 每个可见页面仍最多每 30 秒一次 `/approvals/stats`，暂停时为零。

## 验证

- `approvalStatsRefresh.test.ts` 增加「暂停后即使可见也不刷新」；`useApprovalStats` 增加
  `autoRefreshEnabled`/`autoRefreshError`/`setAutoRefresh`，关闭时清 listener/interval，
  重新开启立即补拉。
- 前端 **32 files / 161 tests**、`tsc`、`oxlint` 0/0（145 files）、`oxfmt --check` 153 files、
  `pnpm build` 2947 modules 通过；后端未改，沿用 537+42 / 576+3 / 579。

## 待定

- 是否按账号/浏览器持久化开关（需要新的偏好键与账号切换清理）。
- 是否在失败提示里展示错误类型/下一次重试时间。
- 是否允许自定义刷新间隔，而不只固定 30 秒。
