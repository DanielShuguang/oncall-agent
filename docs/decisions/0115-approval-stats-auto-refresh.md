# ADR-0115：审批统计自动刷新

## 背景

`ApprovalsPage` 顶部的积压/等待统计、按日趋势、按小时分布与分组表都是「请求时快照」：
进入页面拉一次，切 7/30/90 天或分组时再拉一次。管理员停留在页面上盯积压时，数据不会
自己更新；README 已知局限明确写了「页面停留不会自动更新」。这会让值班人员误判积压是否
已经下降，只能手动切窗口或刷新整页。

## 备选方案

| 方案 | 取舍 |
|---|---|
| 保持只读快照，手动切窗口/刷新整页 | 实现为零，但页面停留期间数据必然过期 |
| 服务端 SSE / WebSocket 推送 | 需要新连接、心跳、鉴权与多副本广播，超出本页当前需求 |
| 服务端加短 TTL 缓存 | 减少查询但不会让页面拿到新数据，仍需客户端触发 |
| 前端定时轮询（采用） | 不改接口、无迁移；用页面可见性和静默失败控制副作用 |

## 决策

1. `useApprovalStats` 在页面可见时每 **30 秒**拉一次 `/approvals/stats`，参数沿用当前
   `statsDays` 与 `statsGroup`；切窗口/分组时重置定时器，避免旧参数继续轮询。
2. 只在 `document.visibilityState === 'visible'` 时轮询；标签页重新可见时立即补拉一次，
   隐藏期间不发请求。
3. 顶部显示「更新于 HH:mm:ss」与「页面可见时每 30 秒自动刷新」，并提供「刷新」按钮；
   手动刷新期间按钮显示「刷新中…」。
4. 自动刷新失败不覆盖上一份统计（静默失败，等下一轮或手动刷新）；手动刷新失败才回到
   空统计，避免后台网络抖动把可用的积压数据清空。
5. 仍是请求时快照，不做服务端推送、不做告警、不持久化刷新状态；第一次进入页面仍由
   原有 effect 拉取，自动刷新只负责后续更新。
6. 请求令牌仍用于丢弃旧响应；自动刷新与手动刷新共用同一令牌，后发请求覆盖先发结果。

## 后果

- 页面可见时每个管理员每 30 秒最多一次 `/approvals/stats`，按当前 7/30/90 天窗口与分组
  计算；隐藏标签页不产生流量。
- 数据最多滞后约 30 秒；不是实时推送，也没有「数据新鲜度」服务端保证。
- 自动刷新失败是静默的，界面继续显示上一份统计与上次更新时间；管理员可手动刷新确认。
- 无新接口、无表/迁移、无权限变化；审批列表本身不会因此自动刷新。

## 验证

- `web/src/features/console/approvalStatsRefresh.ts`：30 秒常量、可见性判断、
  `formatStatsUpdatedAt` 时间格式。
- `approvalStatsRefresh.test.ts` 3 用例；`useApprovalStats` 增加 `lastUpdatedAt`/`refreshing`；
  `ApprovalStatsPanel` 增加刷新按钮与自动刷新说明。
- 前端 **32 files / 160 tests**、`tsc`、`oxlint` 0/0（145 files）、`oxfmt --check` 153 files、
  `pnpm build` 2947 modules 通过；后端未改，沿用 537+42 / 576+3 / 579。

## 待定

- 是否根据错误率或页面停留时长自适应调整间隔。
- 是否需要服务端 ETag/Last-Modified 减少重复传输。
- 是否在统计里加自动刷新暂停开关；当前只由页面可见性控制。
- 是否把同一机制复用到置顶/恢复审计统计卡；当前只改审批统计。
