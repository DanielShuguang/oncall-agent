# 0039 · 会话列表按标题搜索

## 背景

[ADR-0030](0030-session-list.md) 给了会话列表，[ADR-0033](0033-session-history-pagination.md)
又补了翻页；但会话一多，用户只能一页页翻。ADR-0033 的待定里写着「会话搜索、重命名、
删除、未读标记：都需要新的产品语义，v1 不做」，README 的已知局限也明确写了「没有会话搜索」。

会话是 `runs.session_id` 的投影，没有 `sessions` 表；列表标题取自该会话**最早一条非空
`input`**。在不引入新表、不改保留策略的前提下，可以先把「按标题找会话」做出来：搜索范围
收窄为投影标题，不碰回答正文、工具结果与审批理由。

## 备选方案

| 方案 | 结论 |
|---|---|
| 搜 `runs.output` / 事件全文 | 需要中文分词、索引与新的权限/保留语义；正文 180 天后会被清空，搜索结果会随保留策略漂移。否决 |
| 前端只过滤已加载的 20 条 | 用户会以为搜的是全部历史，实际只过滤当前页，误导性强。否决 |
| 管理员跨用户检索 | 需要新的权限模型与审计口径，超出本次范围。否决 |
| 新建 `session_search` 表/物化标题 | 会话是投影，标题来自 run；多一张表就多一份一致性负担，收益不足。否决 |
| 复用投影标题，SQL 子串匹配 | 只读、无迁移、与现有 keyset 分页天然兼容。采纳 |

## 决策

1. `GET /api/sessions` 增加可选 `q`：只匹配**投影标题**（首条非空 `input` 的完整原文；
   列表展示时仍截到 60 字符），大小写不敏感子串；`q` 长度 1–100，前后空白裁掉，裁完为空
   按「没有搜索」处理。
2. 只搜本人会话，没有管理员旁路；不搜回答正文、工具结果、审批理由，也不搜已被正文保留期
   清空的标题（此时 `title` 为 `null`）。
3. 与 [ADR-0033](0033-session-history-pagination.md) 的 keyset 分页共用：先过滤再按最近
   活动排序，`cursor` 的语义、404/400/503 行为都不变；翻页期间有新 run 时会话仍可能
   重复或跳过。
4. Postgres 用 `row_number() over (partition by session_id order by started_at, id)`
   子查询取每个会话首个非空 `input`，再用
   `strpos(lower(input), lower(q)) > 0` 过滤；不用 `LIKE`，避免 `%` / `_` 被当成通配符。
   标题查询复用同一子查询，不产生 N+1。
5. 不新增表、不新增索引、**无迁移**；沿用 `idx_runs_user_session_time`。
6. 前端在输入框回车或点「搜索」时才提交，不做每击键请求；清空后提交恢复完整列表；
   空态区分「没有匹配的会话」与「还没有历史会话」。
7. 搜索词不写进 URL、不记搜索历史、不做高亮与相关性排序。

## 后果

- 标题不含关键词的会话搜不到，哪怕对话内容相关；标题被正文保留期清空后同样搜不到。
- 结果按最近活动排序，不是相关性排序；没有分页快照，翻页期间会话移动仍可能重复/跳过。
- 大小写折叠只对 ASCII 有效，中文按字面子串匹配。
- `q` 只做长度校验，不做分词或查询语法解析；超长返回 422。
- 搜索与列表共用同一个接口，前端不需要新的状态机；「加载更多」自动带当前搜索词。

## 验证

- 默认 `pytest`：**459 passed + 34 skipped**；真实 Postgres：**490 passed + 3 skipped**；
  再加 Redis：**493 passed**。
- 接口用例覆盖大小写、`%` 按字面量、纯空白 `q` 回退全列表、无匹配空列表、搜索 + keyset
  翻页、`q` 101 字符 422；`test_store_contract.py` 在内存与真实 PG 上共用同一组搜索断言
  （含中文子串与 ASCII 大小写）。
- 前端 `tsc --noEmit`、`pnpm test` **65 tests / 13 files**、`oxlint` 0/0、`oxfmt --check`
  70 files、`pnpm build` 通过。
- 无迁移；检索参数、提示词、多轮历史未改，未重跑评测。
